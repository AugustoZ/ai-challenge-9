# Change: Порты поиска и хранения памяти (memory-search-ports)

## Зачем

Долговременная память (change memory-layers) сейчас жёстко связана с двумя
решениями: JSON-файл как хранилище (`LongTermMemoryStore`) и keyword-скоринг
внутри `MemoryRetriever`. Запланированное развитие — полнотекстовый поиск
(FTS5), векторный поиск по эмбеддингам и полноценный RAG — потребовало бы
переписывания фичи, а не замены бэкенда.

Нужен рефакторинг без изменения поведения: хранение и поиск уходят за порты,
текущие реализации становятся первыми реализациями портов, конфиг получает швы
для будущих стадий. Итог — переход к FTS/вектору/RAG сводится к новым
реализациям интерфейсов плюс миграции данных.

## Ключевые решения

1. **Порты вместо перемычек (гексагональный стиль).**
   `MemoryRepository` — CRUD-контракт долговременной памяти (list/counts/get/
   add/update/delete). `MemorySearchEngine` — поисковый контракт
   (`search(query, kind?, limit): List<ScoredMemoryEntry>`). `EmbeddingProvider`
   (`embed(text): FloatArray`) — контракт эмбеддингов стадии 2 (в этом чейндже
   только интерфейс и тестовый дубль, прод-реализация не добавляется).
2. **Текущие реализации — первые реализации портов.** `LongTermMemoryStore`
   реализует `MemoryRepository` (сигнатуры совпадают). Keyword-скоринг
   (токены ≥3 символов рус+лат; title×3, tags×2, content×1; score>0; ties по
   updatedAt desc) выносится из `MemoryRetriever` в `KeywordMemorySearch`
   без изменения логики.
3. **`MemoryRetriever` — оркестратор мини-RAG.** Профили — всегда из репозитория
   (кап 10); релевантные decision/knowledge — из поискового движка (limit 6);
   далее прежние бюджеты (1800/2400 символов) и формат блока. Поведение
   байт-в-байт прежнее; существующие тесты `MemoryRetrieverTest` проходят с
   точечными правками точек сборки.
4. **Конфиг-швы (доктрина: старый config.json работает).** `AppConfig.memory:
   MemoryConfig? = null` с полями `search: String? = null` (null/"keyword" —
   текущее поведение) и `embedding: EmbeddingConfig? = null` (url, model,
   apiKey?, dimensions?). Фабрика `MemorySearchEngine.forConfig`: неизвестное
   значение `search` — ошибка старта с русским текстом (fail-fast, не тихий
   фолбэк).
5. **Контрактные тесты — страховка замены.** Абстрактный
   `MemoryRepositoryContractTest` фиксирует обязательные поведения (CRUD,
   counts, фильтры kind/q, капы, персист roundtrip). Текущая и ВСЕ будущие
   реализации (SQLite и др.) обязаны проходить этот набор без изменений.
6. **Схема записи стабильна.** `{id, kind, title, content, tags, source,
   createdAt, updatedAt}` не меняется; `ignoreUnknownKeys` гарантирует, что
   новые поля будущих стадий читаются старым кодом. Эмбеддинги в JSON-записи
   не хранятся — они принадлежат векторному хранилищу стадии 2.

## Эволюционный путь (стадии)

- **Стадия 0 (этот чейндж):** порты + keyword-реализация + конфиг-швы +
  контрактные тесты. Поведение прежнее.
- **Стадия 1:** SQLite-репозиторий (один файл БД в dataDir, миграция
  `longterm.json` при старте) + FTS5-поиск за `MemorySearchEngine`.
- **Стадия 2:** `EmbeddingProvider` (OpenAI-совместимый `/embeddings`) +
  векторный индекс (sqlite-vec или персистимый in-memory) + гибридный поиск
  (keyword+vector, reciprocal rank fusion).
- **Стадия 3:** полный RAG: чанкинг документов, цитаты в ответах агента
  (`memory_recall` возвращает источники), расширение ретривера на рабочую
  память и сессии.

## Edge cases

- `memory.search = "fts"` при отсутствии реализации → приложение не стартует,
  ошибка с русским текстом и перечислением доступных значений.
- Пустой запрос/пустой индекс → движок возвращает пустой список, блок памяти
  строится из одних профилей (как сейчас).
- `limit` больше числа релевантных записей → возвращаются все релевантные.
- Конкурентные записи — без изменений (synchronized в реализации репозитория).

## Что не делаем (вне рамок)

- SQLite, FTS5, эмбеддинги, векторные индексы и RAG-пайплайн — только контракты
  и швы для них (стадии 1–3).
- Миграция данных — не требуется (хранилище не меняется).
- Изменение формата блока памяти, капов и API — запрещено (нерегрессия).
