# Спецификация: comparison-mode

> Дельта change `add-context-strategies`. Расширение capability из
> change `add-history-compression`.

## ADDED Requirements

### Requirement: Стратегия на каждую колонку зеркала

Каждая колонка зеркального режима получает выбранную стратегию из
набора Выкл | Окно | Сводка | Факты. Стратегия Ветки в колонках
недоступна. Выбор стратегий колонок — единственный per-side параметр
зеркала; параметры (окно, пороги, бюджеты) остаются глобальным
конфигом.

#### Scenario: Две разные стратегии в зеркале

- КОГДА зеркальный режим включён, для колонок выбраны Окно и Факты
- ТОГДА каждая колонка прогоняет вопрос со своей стратегией
- И заголовки колонок отражают выбранные стратегии (при смене выбора
  labels меняются)
- И payload каждой стороны — базовый payload + свой `sessionId` +
  `judgeEnabled=false` + `contextStrategy` стратегии колонки, без
  `compressionEnabled`
- И зеркальный прогон не активирует ветвление (Ветки в выборе нет)

### Requirement: Заголовки колонок отражают стратегии

Заголовки (labels) колонок показывают выбранные стратегии, а не
статичные «с компрессией»/«без компрессии».

### Requirement: Per-side payload без legacy-флага

Payload каждой стороны: базовый payload + собственный `sessionId` +
`judgeEnabled: false` + `contextStrategy` равной стратегии колонки.
Поле `compressionEnabled` в per-side payload НЕ передаётся: стратегию
полностью определяет `contextStrategy`.

### Requirement: Метрики по каждой колонке

Токены, бейдж «Сводка применена» и статус сводки отображаются по
каждой колонке (поведение прошлой итерации сохранено): колонка без
«Сводки» бейджа не показывает, «н/д» при null usage — как раньше.

#### Scenario: Сводка применена только в одной колонке

- КОГДА левая колонка — Сводка (summary применён), правая — Окно
- ТОГДА бейдж «Сводка применена» и статус сводки видны в левой
  колонке, в правой — нет
- И токены показаны по каждой колонке отдельно

### Requirement: Изоляция ошибок сторон

Отказ одной стороны (сеть, 5xx, ошибка стрима) оседает карточкой в
её собственной колонке: вторая колонка продолжает работать, общий
прогон не падает.

#### Scenario: Левая колонка упала

- КОГДА стрим левой колонки завершился ошибкой
- ТОГДА в левой колонке карточка ошибки
- И правая колонка доводит ответ до конца

### Requirement: Twin-сессии не ветвятся

Twin-сессии зеркального прогона никогда не получают стратегию
branching: авто-форк в зеркале не срабатывает, маркеры checkpoint в
twin-лентах отсутствуют.
