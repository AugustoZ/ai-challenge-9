# Спецификация: facts-memory

> Дельта change `add-context-strategies`. Новая capability.

## ADDED Requirements

### Requirement: Блок фактов в запросе

При разрешённой стратегии facts запрос содержит блок фактов —
system-сообщение, стоящее ПОСЛЕ главного system-промта и ПЕРЕД
историей. Блок формируется из фактов сессии (строки «ключ: значение»);
если фактов нет, блок не подставляется.

#### Scenario: Запрос с фактами

- КОГДА разрешена стратегия facts, у сессии 4 факта и 7 сообщений
- ТОГДА запрос содержит system-блок фактов (4 строки «ключ: значение»)
  сразу после главного system-промта
- И после блока идёт история: последние 3 сообщения (окно 3 — константа
  спецификации) с действующим turn-boundary guard

### Requirement: Контекст = факты + последние 3 сообщения

История в запросе при стратегии facts — последние 3 сообщения (окно 3
жёсткая константа, per-request параметра нет) с тем же turn-boundary
guard, что у Окна: срез не начинается с osиротевшего role="tool".
Остальная история в запрос не подставляется, хранилище не
изменяется (non-destructive view, как у Окна). Если фактов ещё нет,
в запрос идут только последние 3 сообщения as-is.

### Requirement: Экстракция после ответа ассистента

Извлечение фактов выполняется ПОСЛЕ завершения ответа ассистента и
только при активной стратегии facts: при любой другой разрешённой
стратегии вызов экстрактора не выполняется.

### Requirement: LLM возвращает полный обновлённый KV-JSON

За один вызов экстрактор получает от LLM полный обновлённый KV-JSON —
массив объектов `{key, value}`, максимум 10 фактов. Результат
заменяет факты сессии целиком: инкрементальных патчей нет.

#### Scenario: Экстракция после ответа

- КОГДА ассистент завершил ответ на запрос со стратегией facts
- ТОГДА выполняется один вызов экстрактора, и его KV-JSON (массив
  `{key, value}`, не более 10 фактов) сохраняется как новые факты сессии
- И при следующем запросе со стратегией window/summary/off экстрактор
  не вызывается

### Requirement: Сбой экстракции не ломает чат

Ошибка экстракции (сеть, 5xx, битый JSON) ловится: сохраняется
ПРЕЖНИЙ набор фактов сессии, основной ответ возвращается 200 как
обычно. Чат не зависит от успеха экстракции.

#### Scenario: Провайдер экстракции недоступен

- КОГДА вызов экстракции завершился ошибкой после ответа ассистента
- ТОГДА /api/chat отвечает 200 с непустым ответом
- И прежние факты сессии сохранены без изменений

### Requirement: Факты хранятся на сессии

Факты живут в поле сессии (`Session.facts`), переживают перезапуск
сервера: FileSessionStore сохраняет и загружает их. Старые файлы
сессий без этого поля читаются без ошибки (факты пусты).

#### Scenario: Факты пережили перезапуск

- КОГДА сессия с 3 фактами была сохранена, сервер перезапущен, сессия
  загружена из файла
- ТОГДА 3 факта доступны в запросе со стратегией facts
- И файл сессии, записанный до появления поля фактов, загружается без
  ошибки с пустыми фактами

### Requirement: UI — панель фактов read-only

Во фронтенде при стратегии facts показывается панель фактов списком
«ключ: значение». Панель read-only: ручной правки и удаления фактов из
UI нет; обновляется из полей ответа.

### Requirement: Mock-LLM детерминирован для фактов

`scripts/mock-llm.py` распознаёт маркер «Извлечение фактов» в запросе и
отвечает детерминированным KV-JSON (массив `{key, value}`, не более
10), чтобы экстракция покрывалась безсетевыми тестами и QA, по
прецеденту маркера суммаризационного запроса.
