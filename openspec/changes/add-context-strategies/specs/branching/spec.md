# Спецификация: branching

> Дельта change `add-context-strategies`. Новая capability.

## ADDED Requirements

### Requirement: Ручная развилка — единственный способ создания ветки

Ветвление только ручное: близнец-ветка создаётся исключительно явным
действием пользователя — эндпоинт `POST /api/session/{id}/branches`
(без тела) делает снимок текущего активного состояния (messages,
summary, facts) в новую ветку «Ветка <seq>» и НЕ переключает активную
ветку. Автоматических форков по счётчику сообщений нет: сколько бы
обменов ни прошло, новые ветки без ручной развилки не появляются, и
служебных записей об автоматических развилках в ленте нет. Ответ —
запись созданной ветки в той же форме, что у списка веток
(branchId/label/forkUserCount/userCountSinceFork/messageCount/active,
active=false). Неизвестная сессия — 404 с текстом ошибки; при
достигнутом капе 8 снимков-веток — 409, состояние не дублируется.

#### Scenario: Пользователь создал развилку

- КОГДА пользователь нажимает «Развилка» при активной стратегии «Ветки»
- ТОГДА создаётся близнец-ветка со снимком текущего состояния
- И панель веток обновляется, активная ветка не меняется

#### Scenario: Лимит веток исчерпан

- КОГДА достигнут лимит веток и пользователь нажимает «Развилка»
- ТОГДА ответ 409
- И в ленту выводится сообщение о достигнутом лимите, ветка не создаётся

#### Scenario: Неизвестная сессия

- КОГДА ручная развилка запрошена для несуществующей сессии
- ТОГДА ответ 404 с текстом ошибки по-русски

#### Scenario: Форк только вручную

- КОГДА в диалоге при стратегии «Ветки» прошло любое число обменов
  (в том числе больше пяти) без нажатия «Развилка»
- ТОГДА новые ветки не создаются: в перечне только живое активное состояние
- И лента не содержит служебных записей о развилках

### Requirement: Идентификаторы и метки веток

Ветка получает label вида «Ветка <seq>» (порядковый номер развилки
в сессии). Активная ветка сохраняет свой id и label.

### Requirement: Селектор веток виден только под стратегией «Ветки»

Плоский селектор веток виден ТОЛЬКО при активной стратегии «Ветки» —
на любое число записей, включая одну (живой корень) и пустой перечень.
Любая другая стратегия и зеркальный режим скрывают селектор целиком,
даже если в сессии уже есть ветки: панель принадлежит стратегии, а не
данным. Первая запись перечня — живое активное состояние; для исходной
истории она носит label «Основная» и не кликабельна (активировать корень
POST-ом нельзя). Клавиша «+ Развилка» в конце ряда чипов — единственный
способ создать ветку; после успеха в ленту пишется служебная запись
о созданной ветке («Чекпоинт: создана …») и селектор перечитывается.

#### Scenario: Селектор виден сразу и только под «Ветками»

- КОГДА пользователь включает стратегию «Ветки» (в новом диалоге или
  в сессии с любым числом веток)
- ТОГДА селектор веток появляется сразу — с чипом «Основная» (не кликабелен)
  и клавишей «+ Развилка»
- И при смене стратегии на любую другую селектор скрывается целиком,
  даже если в сессии уже есть ветки

### Requirement: Эндпоинт переключения веток

Переключение — эндпоинт `POST /api/session/{id}/branches/activate` с
телом `{branchId}`: активное состояние сессии свопится с копией
выбранной ветки без потерь — прежнее активное состояние сворачивается
в новую запись ветки, активной становится снимок выбранной.

#### Scenario: Переключение эндпоинтом

- КОГДА выполнено `POST /api/session/{id}/branches/activate` с id ветки
- ТОГДА `GET /api/session/{id}` возвращает сообщения этой ветки
- И последующий запрос идёт в переключённую ветку
- И прежнее активное состояние сохранено отдельной записью ветки — своп без потерь

### Requirement: branchId в запросе

Поле `ChatRequest.branchId`: если указано и не совпадает с активной
веткой — сервер активирует эту ветку ПЕРЕД обработкой запроса;
null → обрабатывается активная ветка.

### Requirement: Кап 8 веток на сессию

В списке `branches` сессии не более 8 снимков-веток; активное состояние
живёт отдельно (в `Session.messages/summary/facts`). При достижении капа
ручная развилка отклоняется (409): состояние не дублируется, диалог
продолжается в активной ветке.

### Requirement: Персист и back-compat

Ветки и метки сохраняются в FileSessionStore (fields `branches`,
`activeBranchId`, `branchSeq`). Старые JSON-файлы сессий без новых
полей читаются без ошибки: веток нет, активна исходная история.
Миграция и перезапись старых сессий не выполняются.

### Requirement: Контекст при стратегии branching — полная история ветки

Контекст при разрешённой стратегии branching — полная история АКТИВНОЙ
ветки (как при off) + действующие капы (trim/trimContext поверх).
Пара assistant(tool_calls) → tool в истории ветки не рвётся ни
на момент форка, ни в запросе.

### Requirement: Зеркальный режим не ветвится

В зеркальном режиме ветвление не активируется: twin-сессии никогда не
получают стратегию branching, ручная развилка в колонках зеркала
недоступна, панель веток скрыта.
