# Change: Персонализация «Штурмана»: пользователи, ПИН, предпочтения, изоляция

## Зачем

«Штурман» сейчас знает об одном безликом пользователе: сессии, рабочая
память, долговременная память и журнал запросов лежат в общих хранилищах,
концепта «кто» нет. Два человека, использующие одно развёртывание, делят
сессии и диалоги, а записи долговременной памяти, написанные одним,
инъецируются в промпт другого.

Нужна персонализация поверх существующей модели памяти (change
`memory-layers`): PIN-вход, полная изоляция данных каждого пользователя и
опросник предпочтений (форма обращения, тон, язык, структура, длина,
избегаемые темы, интересы), который сервер применяет к каждому LLM-запросу.
Результат: персонализированный агент, адаптированный под каждого
пользователя.

## Домены

| Домен | Что хранит | Где живёт | Жизненный цикл |
|-------|------------|-----------|----------------|
| Пользователь | Имя + хеш ПИНа | НОВОЕ: `dataDir/users/{userId}.json` | Создаётся и удаляется пользователем |
| Токен | Сессия авторизации (token → userId) | Только в памяти сервера | Рестарт сервера = пере-вход всех |
| Предпочтения | 7 ответов опросника | НОВОЕ: `dataDir/preferences/{userId}.json` | Пер-юзер; дефолты при прерванном визарде |
| «Шумахер» | Legacy-миграция | Наследует все данные без владельца | Одиночная, идемпотентная |

## Ключевые решения

1. **PIN-авторизация, а не пароли.** ПИН ровно 4 цифры на пользователя,
   хранится как `SHA-256(salt + ПИН)` (JDK, без новых зависимостей),
   сравнение constant-time (`MessageDigest.isEqual`). Имя: 1..25 символов
   после trim (кириллица/латиница/цифры/спецсимволы, контрольные символы
   запрещены). Дубликаты имён разрешены: различают ПИНЫ. 3 неудачные
   попытки → кулдаун 30 секунд (429 с русским текстом); успех сбрасывает
   счётчик.
2. **Токен в заголовке `X-Auth-Token`.** SecureRandom 32 байта Base64URL,
   только в памяти сервера: без JWT, без refresh, без персистентности. Все
   запросы, включая SSE, несут заголовок. Токены не переживают рестарт
   сервера, рестарт = пере-вход (задокументировано).
3. **Центральная защита, один choke point.** Ktor-intercept
   (`ApplicationCallPipeline.Plugins`) в начале `aiRoutes()`:
   whitelist = {`POST /api/auth/login`, `GET /api/auth/users`,
   `POST /api/auth/users`, статика `/`}; всё остальное без валидного
   `X-Auth-Token` → 401 `{"error": "Требуется вход"}`. Проверки токена
   НЕ рассыпаются по call-site'ам. Таблица disposition всех 22
   существующих роутов зафиксирована в `specs/user-auth/spec.md`.
4. **«Предпочтения», а не «profile».** Новый домен назван
   «Предпочтения»/preferences: имя «profile» занято memory-kind
   (`kind: profile` в долговременной памяти), коллизия в API и промптах
   невозможна. Таксономия memory-kind не меняется; записи с
   `kind="profile"` НЕ мигрируются в опросник и остаются памятью
   «Шумахера».
5. **Полная изоляция per-user.** Сессии (`Session.userId`), рабочая память
   (завязана на сессии пользователя), долговременная память
   (`dataDir/memory/{userId}/longterm.json`), предпочтения
   (`dataDir/preferences/{userId}.json`). Кросс-доступ к чужим ресурсам =
   404, а не 403 (существование ресурса не раскрывается). Журнал
   запросов: записи помечаются `userId`, `GET /api/log` отдаёт только
   свои.
6. **Инъекция предпочтений в одной точке.** System-сообщение с блоком
   «Предпочтения пользователя» дописывается хвостом семени ПОСЛЕ
   `SessionHistory.trim` в том же слоте, что и блок памяти (Routes.kt,
   точка сборки memory-сообщения): сначала блок предпочтений, затем блок
   памяти. Работает во всех режимах (прямой ответ, пошаговое решение,
   агент): `handleSingle` и `handleAgent`. Саб-вызовы (извлечение фактов,
   сводка истории, судья) предпочтений НЕ получают. Бюджет блока ≤ 2500
   символов.
7. **Длина = текстовая инструкция, не `max_tokens`.** Бэкенд и так
   игнорирует generation-параметры модели; поле «длина» становится строкой
   в блоке («Длина ответов: средне (ориентир ~3000 токенов)»). Слайдер
   «Топливо» остаётся жёстким капом и имеет приоритет. Тесты не
   ассертят токен-каунты.
8. **Идемпотентная миграция «Шумахера».** При старте: если пользователя с
   именем «Шумахер» НЕТ и есть legacy-артефакты (сессии с `userId == null`
   или файл `dataDir/memory/longterm.json`) → создать пользователя (PIN
   генерируется SecureRandom и печатается в stdout ОДИН раз с пометкой
   миграции), записать все осиротевшие сессии и файл долговременной
   памяти за него. Второй бут = no-op. Пустой `dataDir` → «Шумахер» НЕ
   создаётся (защита от ре-миграции после удаления пользователей).
9. **Удаление пользователя: каскад + защита последнего.**
   `DELETE /api/auth/users/{id}`: файл пользователя,
   `preferences/{userId}.json`, `memory/{userId}/`, его сессии (включая
   файлы рабочей памяти) и отзыв его токенов. Удаление единственного
   оставшегося пользователя → 400 «Нельзя удалить единственного
   пользователя».
10. **Клиент: sessionStorage + централизованный 401.** Токен хранится
    только в `sessionStorage` (`shturman.auth.v1`), не в localStorage.
    Любой 401 из любого API-вызова → logout → экран входа. Заголовок
    `X-Auth-Token` выставляется только в `api/client.ts` и `api/sse.ts`.
    При выходе/переключении пользователя срабатывает reset-лист
    фронтенд-состояния: sessionId, twinRegistry, memory-стор, черновик
    ввода.

## Edge cases

- Подбор ПИНа: 3 неудачи → 30-секундный кулдаун; даже верный ПИН внутри
  кулдауна → 429. Счётчик в памяти и обнуляется рестартом сервера:
  осознанно, это троттлинг, а не криптографическая защита.
- Рестарт сервера: все токены недействительны; `restore()` клиента
  получает 401 → logout → экран входа (сессионные вкладки браузера живут,
  вход повторный).
- SSE mid-stream: уже начатый стрим доигрывается в исходной сессии и для
  исходного пользователя; повторной проверки токена в середине стрима нет.
- Эвикция `MAX_SESSIONS=50` остаётся ГЛОБАЛЬНОЙ, а не per-user: осознанно,
  задокументировано; per-user квоты вне рамок.
- `/api/files` остаётся ОБЩЕЙ файловой песочницей: защищена токеном, но
  содержимое общее для всех пользователей; осознанно, задокументировано.
- Файл предпочтений отсутствует → дефолты (ты/дружелюбный/Русский/текст/
  средне/пусто/пусто); прерванный визард ничего не сохраняет и ничего не
  ломает.
- Legacy-файлы сессий без `userId` читаются с `userId == null`
  (обратная совместимость, `ignoreUnknownKeys`); миграция передаёт их
  «Шумахеру».

## Что не делаем (вне рамок)

- JWT, refresh-токены, персистентные токены, восстановление/смена ПИНа.
- Роли, права, per-user квоты эвикции, per-user модели и температуры.
- i18n интерфейса: UI остаётся русским (предпочтение «Язык» влияет только
  на язык ответов LLM).
- Редактирование предпочтений инлайн-контролами: только через опросник
  (единая модель данных).
- Изменения `AgentLoop.SYSTEM_PROMPT` и таксономии memory-kind; инъекция
  предпочтений в саб-вызовы.
- Миграция записей долговременной памяти с `kind="profile"` в опросник.
