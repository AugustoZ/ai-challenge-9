# Спецификация: Предпочтения пользователя (preferences)

## ADDED Requirements

### Requirement: Опросник из 7 полей

Предпочтения пользователя MUST состоять ровно из 7 полей с допустимыми
значениями:

| Поле | Допустимые значения |
|------|---------------------|
| Форма обращения (`addressForm`) | ты / вы / пилот / гонщик |
| Тон (`tone`) | формальный / дружелюбный / панибратский / роботизированный |
| Язык (`language`) | Русский / Английский |
| Структура ответов (`answerStructure`) | таблицы / текст / стихи / произвольное ≤ 255 символов |
| Длина ответов (`length`) | кратко (≈ 1 тыс. токенов) / средне (до 3 тыс.) / развернуто (≈ 10 тыс.) |
| Избегаемые темы (`avoidTopics`) | произвольное ≤ 1000 символов |
| Интересы (`interests`) | произвольное ≤ 1000 символов |

Хранение: `dataDir/preferences/{userId}.json`. Валидация серверная:
enum-членство, длины, запрет контрольных символов; превышение или
недопустимое значение → 400 с русским текстом. Клиентская валидация
дублирует правила для UX, но не заменяет серверную.

#### Scenario: Допустимые значения сохраняются
- **WHEN** `PUT /api/preferences` с `{"addressForm":"пилот","tone":"панибратский","language":"Английский","answerStructure":"таблицы","length":"развернуто","avoidTopics":"политика","interests":"гонки"}`
- **THEN** 200 с сохранённым объектом; повторный `GET` возвращает те же значения

#### Scenario: Недопустимое enum-значение
- **WHEN** `PUT /api/preferences` с `{"length":"бесконечно", ...}`
- **THEN** 400, текст называет поле и допустимые значения

#### Scenario: Превышение лимитов
- **WHEN** `PUT /api/preferences` с `avoidTopics` в 1001 символ или
  `answerStructure`-«иное» в 256 символов
- **THEN** 400 с текстом о лимите поля

### Requirement: API предпочтений

`GET /api/preferences` MUST возвращать предпочтения текущего
пользователя; при отсутствии файла предпочтений возвращаются
дефолты (ты/дружелюбный/Русский/текст/средне/пусто/пусто).
`PUT /api/preferences` валидирует объект целиком и сохраняет его; успех →
200 с сохранённым объектом. Оба роута защищаются интерцептом
авторизации (без токена → 401).

#### Scenario: Первый запрос без файла предпочтений
- **WHEN** `GET /api/preferences` у пользователя, который ещё не проходил
  опросник
- **THEN** 200 с дефолтными значениями (ты/дружелюбный/Русский/текст/
  средне/пусто/пусто)

#### Scenario: Round-trip
- **WHEN** `PUT` с валидным объектом, затем `GET`
- **THEN** значения совпадают байт в байт; файл
  `dataDir/preferences/{userId}.json` существует

### Requirement: Инъекция блока в каждый запрос

Система MUST добавлять к семени каждого LLM-запроса отдельное
system-сообщение с блоком «Предпочтения пользователя» (строки «Форма
обращения: …», «Тон: …», «Язык: …», «Структура ответов: …», «Длина
ответов: …», «Избегаемые темы: …», «Интересы: …»). Инъекция: в одной
точке, хвостом семени ПОСЛЕ обрезки истории, в том же слоте, что и блок
памяти (сначала предпочтения, затем память); во всех режимах (прямой
ответ, пошаговое решение, агент). Саб-вызовы (извлечение фактов,
сводка истории, судья) блок предпочтений MUST NOT получать. Общий бюджет
блока ≤ 2500 символов; длиннее free-поля обрезаются при рендере.

#### Scenario: Блок присутствует в каждом режиме
- **WHEN** пользователь отправляет сообщение в прямом режиме, в режиме
  «пошаговое решение» и в агентном режиме
- **THEN** каждый запрос к LLM содержит system-сообщение «Предпочтения
  пользователя» с актуальными значениями

#### Scenario: Блок переживает trim истории
- **WHEN** сессия длинная, история обрезается по стратегии контекста
- **THEN** блок предпочтений всё равно присутствует в семени (не срезан)

#### Scenario: Изменение применяется к следующему запросу
- **WHEN** `PUT /api/preferences` сменил «Тон» на «формальный»
- **THEN** следующий запрос к LLM несёт блок с новым значением

#### Scenario: Саб-вызовы без предпочтений
- **WHEN** включена стратегия извлечения фактов и запрос порождает
  саб-вызов к LLM
- **THEN** промпт саб-вызова НЕ содержит блока «Предпочтения пользователя»

### Requirement: Дефолты при прерванном визарде

Прерванный (закрытый) опросник MUST NOT сохранять частичные ответы:
пользователь работает с дефолтными значениями, которые сервер применяет
сам. Повторное открытие опросника возможно из настроек.

#### Scenario: Визард закрыт на втором шаге
- **WHEN** пользователь открыл опросник, ответил на 2 вопроса и закрыл
  окно
- **THEN** `GET /api/preferences` возвращает дефолты; в запросах LLM
  используется дефолтный блок
