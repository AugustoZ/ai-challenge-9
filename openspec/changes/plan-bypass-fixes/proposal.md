# Изменение: Контент-гейт неутверждённой реализации и триггер создания задачи

> Статус: draft. Capabilities: plan-bypass-fixes.
> SDD-фиксация двух обходов FSM, найденных в реальных сессиях (36aebaec,
> 0c79a57d); реализация идёт по `tasks.md` этого change.

## Зачем

Change `task-lifecycle-gates` закрыл обход через таблицу рёбер: EXECUTION
недостижим без PLAN_APPROVED, нелегальный LLM-блок фиксируется отказом на
сессии. На живых сессиях нашлись ещё два реальных обхода:

1. **Код-дамп без объявления перехода** (сессия 36aebaec). На стадии
   PLANNING модель выдала код-дамп (148 КБ кода, 195 фенсов) без блока
   ```task-state```; FSM контролирует только декларации переходов, но не
   контент, и маркер ``` в EXEC_MARKERS позволил бы эвристике продвинуть
   задачу в EXECUTION. Реализация началась без утверждённого плана: на
   PLAN_APPROVED code-dump без блока так же проходит свободно, пока гейт
   не оценивает стадию до перехода.
2. **Триггер создания задачи не сработал** (сессия 0c79a57d). Фраза
   «План не нужен, сразу пиши код крупного приложения для интеграции с
   несколькими платформами: VK, Telegram, Max» не создала задачу:
   «пиши» не входит в подстрочный словарь INTENT_VERBS (там «напиши»),
   счётчик глаголов дал 0, hasIntent = false, FSM вообще не включился.
   Модель спрятала внутренний план в Самописец и строчила код вне
   контроля жизненного цикла.

Change закрывает оба обхода: (1) контент-гейт в
`Routes.finalizeResponse` мягко отклоняет code-dump на
PLANNING/PLAN_APPROVED без объявленного перехода (контент не вырезается,
стадия держится, модель получает причину через инъекцию на следующем
ходу); (2) расширенный триггер создания задачи в `TaskStateHeuristic`
(глагол «пиши» с границей слова + правило «отказ от плана + действующее
слово») включает FSM на явных фразах «без плана, сразу код».

Влияние только на бэкенд и QA-мок: `TaskStateHeuristic.kt`,
`TaskStateJson.kt`, `Routes.kt`, `scripts/mock-llm.py`. Фронтенд и
HTTP-контракты не менялись: строка «Переход отклонён: …» в StatusLine
уже рендерит непустой `taskRejected`, новое поле ответа не нужно
(решение интервью).

### Edge cases

- **Нечётный хвост фенсов.** Нечётное число маркеров ``` в ответе даёт
  незакрытый блок, который считается блоком: blocks = (fences + fences
  % 2) / 2; у незакрытого блока содержимое берётся от первого фенса до
  конца текста (E1).
- **Гейт и нелегальный блок не смешиваются.** Если в ответе есть и
  code-dump, и нелегальный блок ```task-state```, отказом остаётся
  прежний текст о нелегальном переходе, не гейт-текст: гейт срабатывает
  только при `blockProposal == null` (E2).
- **Гейт молчит в трёх случаях.** PAUSED (пауза = Q&A, paused-wins
  авторитетна), taskState = null (обычный чат с примерами кода работает),
  EXECUTION/VALIDATION/DONE (код на этих стадиях легален) (E3).
- **Гейт перекрывает эвристическое продвижение.** EXEC_MARKERS содержит
  маркер ```: без гейта code-dump на PLAN_APPROVED продвинул бы задачу в
  EXECUTION через `infer`. Гейт оценивается на пре-переходной стадии и
  отбрасывает предложение эвристики (E4).
- **Жизненный цикл гейт-отказа.** Отказ пишется в существующее поле
  `lastRejectedTransition`, инъектируется в блок состояния следующего
  хода (на входе следующего хода отказ ещё виден модели), эхо
  `taskRejected` каждым ходом, чистый ход (без фенсов) очищает; два
  гейт-хода подряд перезаписывают одно поле, отказ остаётся один (E5).
- **Граница слова для глаголов.** «запиши заметку в журнал» и
  «пропиши настройки» задач не создают: «пиши»/«опиши» считаются только
  самостоятельным словом, а не подстрокой (E6).
- **NBSP в реплике пользователя.** «Без\u00A0плана, сразу код»
  нормализуется в «без плана, сразу код» до сопоставления: без замены
  сработало бы не ни одно правило (E7).

## Ограничения (G/E/Q)

> Номера: стабильные якоря, код и тесты задач 2-4 ссылаются на них из
> change-документов.

### Глобальные (G)

- **G1** Не добавлять новые HTTP-роуты и новые поля `ChatResponse`:
  отказ живёт в существующем `lastRejectedTransition`, echo
  `taskRejected` существующий.
- **G2** Не менять фронтенд: StatusLine.tsx уже рендерит строку
  «Переход отклонён: …» при непустом `taskRejected` (формулировку
  принимаем).
- **G3** Не вырезать и не модифицировать контент ответа (варианты B/C
  исключены): только мягкий отказ.
- **G4** Не трогать: `TaskStateMachine.kt`,
  схему SessionStore (новые поля/enum), парсинг блока task-state в
  `TaskStateJson` (хелперы фенсов аддитивны), ToolTransport, механику
  паузы/продолжения.
- **G5** Не добавлять «пиши»/«опиши» в подстрочный словарь
  INTENT_VERBS: только как слова с границей слова.
- **G6** Не добавлять конфиг-швы: гейт always-on; коммитов нет
  (конвенция репозитория: рабочее дерево остаётся незафиксированным).

### Краевые (E)

- **E1** Нечётный хвост фенсов считается незакрытым блоком (+1).
- **E2** При нелегальном LLM-блоке приоритет у прежнего текста отказа о
  переходе; гейт-текст не пишется.
- **E3** Гейт молчит: PAUSED, taskState = null, EXECUTION/VALIDATION/DONE.
- **E4** Гейт перекрывает эвристическое продвижение (EXEC_MARKERS по
  ```): стадия держится, предложение отбрасывается.
- **E5** Гейт-отказ виден модели как инъекция на следующем ходу и
  очищается следующим чистым ходом (жизненный цикл как у отказа о
  нелегальном переходе в `task-lifecycle-gates`).
- **E6** «запиши/пропиши/распиши» не создают задач (граница слова);
  «написать» триггером не является.
- **E7** NBSP в реплике пользователя нормализуется в пробел до
  сопоставления.

### Качество (Q)

- **Q1** Тесты без сети (FakeLLMClient); существующие тесты не
  модифицированы: TaskStateHeuristicTest 52/52 (43 прежних + 9 новых),
  TaskStateRoutesTest 43/43 (29 прежних + 14 новых, включая гейт 1-10),
  TaskStateJsonTest 13/13.
- **Q2** Мок: режим `code-dump` аддитивен, скрипт остаётся stdlib-only,
  существующие режимы и SSE-поведение не сломаны.
- **Q3** Мягкий отказ: тело ответа модели в истории (messages)
  побайтово совпадает с выданным reply; клиенту уходит reply со
  стрипнутым блоком task-state, как и прежде.

## Что меняется (сводка)

- `TaskStateHeuristic.kt`: word-verbs `PISHI`/`OPISHI` с границей слова
  («опиши» вынесено из INTENT_VERBS), правило явного намерения
  (PLAN_REJECTION + ACTION_WORDS; PISHI + CODE_WORDS), NBSP-нормализация
  в `hasIntent`; KDoc словарей.
- `TaskStateJson.kt`: аддитивные хелперы `countCodeFences` (цикл
  indexOf, O(n), без regex) и `codeBlocksExceedThreshold` (порог
  blocks ≥ 2 ИЛИ 1 блок > 10 строк).
- `Routes.kt` (`finalizeResponse`): гейт-ветка ПЕРВАЯ в when-блоке
  (оценка на пре-переходной стадии, фенсы по `cleanReply`) +
  `contentGateRejectionDescription(stage, blocks)`; порядок
  существующих мутаций (стрип → fresh read → paused-wins → apply →
  echo) сохраняется.
- `scripts/mock-llm.py`: константа `CODE_DUMP_REPLY` (три код-блока
  без task-state) + режим `code-dump` в `/control` и диспетче.
- Тесты: добавления в `TaskStateHeuristicTest` (позитивы/негативы
  триггера) и `TaskStateRoutesTest` (гейт 1-10); существующие тесты не
  изменены.
- OpenSpec: этот change (сам документ); код и тесты идут по `tasks.md`.

- `TaskStateMachine.kt`, схема SessionStore, парсинг блока task-state,
