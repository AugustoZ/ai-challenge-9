# Spec: «Мини-агент» в Telegram-боте (правки кода проекта)

## ADDED Requirements

### Requirement: Запуск задачи и стейт-машина
Команда `/agent <задача>` в ЛИЧНОМ чате ДОЛЖНА создавать сессию агента
(`AgentSession` per-user, TTL 60 мин) и переводить её в состояние
`TASK_SET`; из любого состояния команда «/agent отмена» ДОЛЖНА сбрасывать
сессию без записи неподтверждённых правок на диск.

#### Scenario: Создание сессии
- **WHEN** пользователь отправляет `/agent добавь поле X в настройки`
- **THEN** сессия создана, задача сохранена полностью (без обрезки),
  бот показывает выбор модели

#### Scenario: Отмена
- **WHEN** пользователь отправляет «/agent отмена» в состоянии
  `EXECUTE` или `AWAIT_CONFIRM`
- **THEN** сессия сброшена, неподтверждённые правки на диск не записаны

#### Scenario: Только личка
- **WHEN** `/agent` отправлен в группу
- **THEN** команда не обрабатывается (гардрейл как у `/create`)

### Requirement: Выбор модели перед задачей
После `/agent <задача>` бот ДОЛЖЕН показать inline-клавиатуру с моделями из
секции `agent.models` config.json (локальная qwen3.5-9b-mlx,
glm-5.3-flash и deepseek-v4-flash на GPUstack); выбор ДОЛЖЕН записываться
в сессию через `callback_query`.

#### Scenario: Выбор модели
- **WHEN** пользователь нажимает кнопку «GLM 5.3 (GPUstack)»
- **THEN** модель записана в сессию, кнопка погашена
  (`editMessageReplyMarkup`), агентный цикл запущен

#### Scenario: Повторное нажатие
- **WHEN** кнопка нажата повторно или другим пользователем после выбора
- **THEN** бот отвечает «выбор уже сделан», сессия не меняется

#### Scenario: Модель недоступна
- **WHEN** выбранная облачная модель вернула ошибку транспорта или ключ не задан
- **THEN** бот сообщает об ошибке и предлагает выбрать другую модель,
  сессия сохраняется

### Requirement: Параметризация провайдера
Вызовы LLM в агентном режиме ДОЛЖНЫ использовать (api_base, model, api_key,
timeout) из записи выбранной модели; дефолт вне агентного режима —
локальная модель без изменений поведения. Для GPUstack: таймаут 300 с,
отключение проверки сертификата только у этого клиента.

#### Scenario: Обычный чат не затронут
- **WHEN** пользователь задаёт вопрос без активной сессии агента
- **THEN** запрос идёт в локальную модель по прежним настройкам

#### Scenario: Секреты
- **WHEN** бот читает api_key из config.json
- **THEN** значение не попадает в логи, отчёты и сообщения

### Requirement: Память сессии
Сессия ДОЛЖНА хранить: полную формулировку задачи, лог шагов (что читал,
что правил, результаты проверок и отказов) и историю диалога; всё это
ре-инжектится в контекст на каждой итерации агентного цикла.

#### Scenario: Уточняющий вопрос
- **WHEN** в ходе задачи пользователь уточняет требование
- **THEN** уточнение попадает в контекст последующих итераций

### Requirement: Чтение файлов проекта
Маркер `<read path="относительный путь">` ДОЛЖЕН читать файл из дерева
`PROJECT_FILES_ROOT`; путь вне проекта, в запрещённом списке
(`config.json`, `.env`, `.git/`, `node_modules/`, `data/`,
`frontend/dist/`, `build/`) или бинарный — отбрасывается с записью
причины в лог шагов.

#### Scenario: Чтение
- **WHEN** модель запросила `<read path="frontend/src/stores/settings.ts">`
- **THEN** содержимое файла (в пределах лимита размера) попало в контекст
  следующей итерации

#### Scenario: Запрещённый путь
- **WHEN** модель запросила `<read path="config.json">`
- **THEN** файл не прочитан, в лог шагов записана причина, модель получила
  отказ

### Requirement: Гейт подтверждения правок
Правки (`<write>`, `<patch>`) ДОЛЖНЫ накапливаться в памяти сессии;
перед записью на диск бот ДОЛЖЕН показать unified-диффы и дождаться
подтверждения пользователя («применяй»); запись — только из состояния
`AWAIT_CONFIRM`; перед записью оригинал бэкапится в `backups/`.

#### Scenario: Подтверждение
- **WHEN** правки готовы и пользователь ответил «применяй»
- **THEN** файлы записаны (оригиналы в `backups/`), переход в `REPORT`

#### Scenario: Отказ
- **WHEN** пользователь ответил «отмена» на показанных диффах
- **THEN** правки отброшены, на диск ничего не записано

#### Scenario: Путь вне проекта
- **WHEN** модель выдала правку на путь вне `PROJECT_FILES_ROOT`
- **THEN** правка отброшена до показа диффов, модель получила отказ

### Requirement: Ограничения цикла
Агентный цикл ДОЛЖЕН делать не более 5 итераций LLM на задачу и применять
не более одной правки за итерацию; итерация без маркеров повторяется
(не более 2 повторов), затем — отчёт о неудаче и сброс сессии.

#### Scenario: Лимит итераций
- **WHEN** задача не завершена за 5 итераций
- **THEN** бот отправляет отчёт о сделанном, сессия сбрасывается

### Requirement: Верификация правок
После применения правок бот ДОЛЖЕН проверить синтаксис изменённых файлов
(`py_compile` для python, `tsc --noEmit` для TypeScript) и включить
результат в отчёт.

#### Scenario: Синтаксическая ошибка
- **WHEN** после записи py_compile падает на изменённом файле
- **THEN** в отчёте указан файл, строка и текст ошибки, файл восстановим
  из бэкапа

### Requirement: Отчёт об изменениях
По завершении бот ДОЛЖЕН отправить: краткую сводку (маркер `<report>`)
с припиской выбранной модели и списком изменённых файлов, затем каждый
изменённый файл — документом с unified-диффом (не более 5 файлов,
бинарники не прикладываются).

#### Scenario: Один файл
- **WHEN** правка коснулась одного файла
- **THEN** в чат отправлены сводка и документ с диффом этого файла

#### Scenario: Несколько файлов
- **WHEN** правка коснулась 3 файлов
- **THEN** отправлены 3 документа (по диффу на файл) и сводка со всеми путями

#### Scenario: Лимит вложений
- **WHEN** изменённых файлов больше 5
- **THEN** прикладываются первые 5, в сводке — полный список путей

### Requirement: Единственность запуска
Пока сессия агента активна, новый `/agent` ДОЛЖЕН получать ответ «агент
занят»; обычные команды бота (`/ask`, `/deps`, `/help`) ДОЛЖНЫ работать
после завершения задачи.

#### Scenario: Повторный запуск
- **WHEN** пользователь отправляет `/agent …` при активной сессии
- **THEN** бот отвечает «Агент занят…» и предлагает «/agent отмена»
