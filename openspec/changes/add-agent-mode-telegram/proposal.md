# Change: «Мини-агент» в Telegram-боте — правки кода проекта по задаче

## Зачем

Бот отвечает на вопросы, но не умеет работать над задачей: нет состояния
между сообщениями, нет чтения/правки файлов проекта, нет отчёта об
изменениях. Хочется: дал боту задачу («добавь поле X в панель настроек»),
выбрал модель — бот сам читает файлы, готовит правки, показывает диффы,
после подтверждения применяет их и присылает отчёт со сводкой и
изменёнными файлами.

Репозиторий правок — `ai-challenge-9` (монтируется боту через
`PROJECT_FILES_ROOT`); правит бот только этот проект и только по
подтверждению пользователя.

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Триггер | `/agent <задача>` в личке, свободная фраза — не ловим | Гардрейл как у `/create`; интент до RAG-роутинга |
| Стейт-машина | `AgentSession` per-user: `IDLE → TASK_SET → MODEL_SELECT → PLAN/EXECUTE → AWAIT_CONFIRM → REPORT → IDLE`, отмена из любого состояния | Однопоточный воркер уже сериализует задания; состояние — надстройка над `Job` |
| Хранение сессии | In-memory `dict[user_id, AgentSession]` + TTL 60 мин (как черновики `/create`); рестарт = сессия потеряна | Персист на диск не нужен для пилота; паттерн уже есть |
| Память сессии | Задача (полный текст) + лог шагов (что читал/правил/результаты) + история диалога `_history_messages` с большей глубиной | Слои по образцу памяти web-версии; лог шагов переиспользуется в отчёте |
| Системный промт | Новый `AGENT_SYSTEM` через `_build_rag_block(system=AGENT_SYSTEM)` | Маркерный протокол уже доказал себя (`<file>/<doc>`); tool-calls 9b-модели не доверяем |
| Протокол правок | Текстовые маркеры: `<read path>`, `<write path>полный текст</write>`, `<patch path>…</patch>`, `<report>итог</report>` | Без JSON-tool-calls: работает на qwen3.5-9b и переносим на glm/deepseek |
| Запись на диск | Новый модуль `project_edit.py` (зеркало `project_files.py`): containment по `normpath` без `resolve()`, скрип служебных путей, лимит размера, бэкап в `backups/` | Симлинки `docs/ru/` — известная ловушка `resolve()`; секреты не трогаем |
| Запрещённые пути | `config.json`, `.env`, `.git/`, `node_modules/`, `data/`, `frontend/dist/`, `build/` | Секреты и артефакты сборки — вне протокола LLM |
| Гейт подтверждения | Правки готовятся в памяти, диффы показываются пользователю, запись — только после «применяй» | Пользователь подтверждает изменения; FSM-состояние `AWAIT_CONFIRM` |
| Верификация после правки | `py_compile` для python, `tsc --noEmit` для TS; полный `npm run verify`/gradle — вне цикла | 9b-модель и 30 tok/s не вытягивают полный тестовый прогон |
| Цикл агента | Максимум 5 итераций LLM на задачу; одна правка за итерацию | Лимит токенов и времени; дегенерация обрывается лимитом |
| Очередь | Отдельный режим `agent` в существующем `_worker`; второй `/agent` при активной сессии → «агент занят» (паттерн «1 активный запуск» пайплайнов) | Длинная задача (до ~10 мин) не должна молча блокировать чат |
| Выбор модели | Inline-клавиатура после `/agent <задача>`: локальная qwen3.5-9b-mlx / `glm-5.3-flash` / `deepseek-v4-flash` (GPUstack, `gpustack.data.lmru.tech`) | Требование пользователя; имена моделей — из `config.example.json` web-версии |
| callback_query | Новая ветка в `_poller_loop`: `answerCallbackQuery` + парсинг `agent:model:<id>`; кнопка одноразовая (`editMessageReplyMarkup`) | Бот на голом Bot API, библиотеки нет; сейчас callback-апдейты дропаются |
| Провайдер | `agent.models` в config.json: `{id, label, api_base, model, api_key_env}`; `_post_chat` параметризуется (api_base, model, key, timeout); дефолт без сессии — локальная | GPUstack: таймаут 300 с (шлюз думает >1 мин), `verify=False` только для этого клиента (сертификат шлюза истёк — как в AIClient web-версии) |
| Отчёт | Сводка из `<report>` текстом + unified-диффы (`difflib` + `render_diff_html` из `file_diff.py`) документами `_send_document` — по файлу на каждый изменённый файл; приписка выбранной модели | Всё из готовых узлов |
| Бюджеты per-модель | Поля в записи модели: timeout, max_tokens, frequency_penalty (локальная — 0.3, облако — по умолчанию) | Дегенерация qwen на длинных ответах лечится penalty, а не промптом |

## Edge cases

- Пользователь пишет в бот во время работы агента → «Агент занят, дождитесь
  завершения или напишите /agent отмена»; обычные команды (`/ask`, `/deps`)
  продолжают работать после завершения задачи.
- «/agent отмена» в любом состоянии → правки, не подтверждённые гейтом,
  на диск не попадают, сессия сбрасывается.
- LLM не выдала ни одного маркера за итерацию → итерация повторяется с
  напоминанием о протоколе, после 2 неудач — отчёт «не смог» и отмена.
- Путь из маркера вне проекта или в запрещённом списке → правка отбрасывается,
  в лог шагов пишется причина, LLM получает отказ и может исправиться.
- Пустой/не-UTF-8 файл на чтение → пропускается с пометкой в логе шагов.
- Облачная модель недоступна (GPUstack упал / нет ключа) → сообщение об
  ошибке, предложение выбрать другую модель, сессия не сбрасывается.
- Нажатие кнопки модели вторым пользователем / повторное нажатие → «выбор
  уже сделан».
- Рестарт поллера в середине задачи → сессия потеряна, пользователь видит
  «Агент перезапущен, задача отменена» на следующее сообщение (TTL-запись).
- Изменённых файлов больше лимита отчёта (5) → прикладываются первые 5,
  в сводке полный список путей.
- В группе `/agent` не активен — только личка (гардрейл как у `/create`).

## Волны

1. Каркас агента: `AgentSession`, FSM, `AGENT_SYSTEM`, режим `agent` в
   роутинге/воркере, селектор моделей в config.json.
2. Выбор модели: inline-клавиатура, `callback_query` в `_poller_loop`,
   параметризация `_post_chat` (локальная + GPUstack, вставка ключа
   пользователем в config.json).
3. Чтение и правка: `project_edit.py` (контainment, бэкапы, маркеры
   `<read>/<write>/<patch>`), цикл агента с лимитом итераций, гейт
   подтверждения с показом диффов.
4. Отчёт: сводка `<report>`, диффы документами, приписка модели; верификация
   `py_compile`/`tsc --noEmit`.
5. Верификация и деплой: py_compile, inline-смоки (стабы `_send_*`/`_generate`
   ДО вызовов хендлеров!), пилот на реальной задаче на каждой модели, рестарт
   прод-поллера со снятым env, проверка лога.
