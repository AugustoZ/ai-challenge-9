# Изменение: FSM состояния задачи

> Статус: draft. Capabilities: `task-state-fsm`.
> SDD-фиксация доработки; реализация идёт по `tasks.md` этого change.

## Зачем

Агент «Штурман» не формализует, на каком этапе задачи он находится: модель
внутренне отслеживает «планирую → делаю → проверяю» по истории диалога, и любой
вопрос пользователя может обойтись повторным объяснением контекста. Паузы нет:
задачу нельзя остановить на середине и продолжить без новых пояснений.

Change вводит конечный автомат состояния задачи: этап (planning / execution /
validation / done), текущий шаг и ожидаемое действие. Состояние живёт на сессии
на время сессии, как facts и summary, видно во фронтенде (бейдж этапа + строка
шага), и пользователь может поставить задачу на паузу на любом этапе и
продолжить без повторных объяснений: сервер каждым ходом подставляет блок
состояния в промпт, и модель продолжает с текущего шага.

Драйвер переходов — гибрид: LLM объявляет переход JSON-блоком ```task-state```
в финальном ответе, сервер валидирует переход по фиксированной таблице рёбер.
Пауза/продолжение — прямое действие пользователя: кнопка UI и команды в чате
без вызова LLM.

## Ключевые решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | **Гибридный драйвер переходов**: LLM выводит JSON-блок ```task-state {"stage":…,"step":…,"expected_action":…}``` в финальном ответе; сервер валидирует переход по таблице рёбер; нелегальный переход → no-op (состояние не меняется, не логгируется как сбой) | Модель знает семантику работы, автомат — закон. Чисто серверная эвристика не знает, когда двигаться вперёд; чистое доверие LLM позволило бы произвольные «прыжки». Валидация держит граф детерминированным |
| 2 | **Фиксированный enum этапов**: planning / execution / validation / done + paused; произвольных стадий нет | Малый фиксированный граф тестируем и предсказуем для UI; этап задачи — продуктовая модель, а не то, что модель должна расширять сама |
| 3 | **Пауза = этап автомата**: переход в PAUSED запоминает `prevStage`, resume — обратный переход в `prevStage` | Не нужно отдельное хранилище под паузу: одно поле, один переход, один resume. Граф сам отвечает на вопрос «откуда продолжить» |
| 4 | **Пауза/продолжение**: кнопка UI (POST-роуты) + ровно 4 команды в чате: «пауза», «/пауза», «продолжить», «/продолжить» (сравнение после trim+lowercase) — обрабатываются ДО LLM-вызова | Пауза должна быть мгновенной и гарантированной: по LLM-пути модель могла бы ответить «хорошо, поставлю на паузу» и не поставить. Точное совпадение: «сделай паузу» — НЕ команда (отдельный негативный тест). Английских алиасов нет |
| 5 | **Стрип блока ```task-state```** из ответа ДО записи в историю и ДО judge; фронтенд-фильтр при рендере журнала — defense-in-depth | Блок — серверный протокол, не пользовательский текст. Попадая в историю, он бы повторялся в ответах модели и мелькал в Бортовом журнале |
| 6 | **Fresh re-read + paused-wins** в `finalizeResponse`: LLM-переход применяется только после свежего перечитывания store; если текущий этап == PAUSED → no-op | Гонка: пауза, поставленная в полёте (кнопкой или командой), должна всегда побеждать переход из ответа, сгенерированного до паузы. Параметр `session` в finalizeResponse — устаревший снимок; паттерн свежего перечитывания — тот же, что у currentFacts |
| 7 | **Echo `taskState` в каждом `ChatResponse`** (включая null) | Фронт получает состояние с каждым ходом без доп. запроса; кнопка и бейдж всегда актуальны |
| 8 | **Ветки не захватывают taskState**: в снимок Branch состояние не входит; осознанное ограничение, задокументировано KDoc на Branch и этим change | Состояние — общее на сессию, как facts; захват в снимки веток создал бы второй источник истины и осложнил resume |
| 9 | **Контракт API**: POST `/api/task/pause` и POST `/api/task/resume`, body `{sessionId}`, ответ `{taskState}`; 404 на неизвестную сессию; идемпотентны (повторная пауза — без ошибки, пауза при null → no-op + `{taskState: null}`); оба роута в таблице защищённых и в `AuthInterceptTest` | Отдельный контракт от `/api/chat`: пауза не должна ждать хода ответа, а неизвестная сессия — это ошибка, а не тихий no-op. Защита — по образцу остальных мутабельных роутов |
| 10 | **Персистентность на время сессии**: поле `Session.taskState: TaskState? = null` (default для back-compat) + мутаторы `updateTaskState`/`getTaskState` в InMemory и File сторах | Нет нового хранилища: состояние живёт и умирает с сессией; старые файлы сессий на диске читаются с null |
| 11 | **Инъекция состояния в промпт** — эфемерная system-строка в seed `handleAgent` (зеркало preferences/memory): этап + шаг + ожидаемое действие; paused-вариант — «не объявляй переходы»; null-вариант — «задача не начата». В `Session.messages` строка не попадает | Продолжение без повторных объяснений: модель видит текущий шаг каждый ход. Эфемерность: история не растёт протокольным текстом |
| 12 | **Никаких серверных автопереходов**: только валидированный LLM-edge + пауза/продолжить (API и команды); парсится только финальный reply (не итерации AgentLoop); несколько блоков → последний; капы step ≤ 120 / expected_action ≤ 200 символов | Автопереходы («прошло N сообщений — валидация») конфликтовали бы с суждением модели и ломали семантику паузы. Капы защищают промпт от разрастания |

## Edge cases

- **Несколько блоков в ответе.** Два или больше ```task-state``` блока: парсинг
  берёт последний; стрип удаляет все.
- **Сбой парсинга.** Блок отсутствует, JSON битый, stage со значением вне enum
  → null → состояние не меняется, ответ возвращается как обычно (no-op, не
  failure).
- **Пауза без активной задачи** (`taskState == null`): no-op + системное
  сообщение «Нет активной задачи»; API отвечает `{taskState: null}`.
- **Пауза в полёте.** Пауза, поставленная до финализации хода, побеждает
  LLM-переход из этого хода (fresh re-read + paused-wins).
- **Отмена стрима** (cancelled): финализация не выполняется — taskState
  не тронут.
- **Обычное сообщение во время паузы.** Агент отвечает (инъекция —
  paused-вариант с запретом объявлять переходы), состояние не двигает;
  авто-resume по обычному сообщению не происходит.
- **«Сделай паузу» — не команда.** Перехватываются только точные совпадения
  после trim+lowercase; всё остальное уходит в обычный LLM-путь (негативный
  тест).

## Что меняется (сводка)

- Новый пакет `com.example.aiweb.task`: `TaskStage` (enum), `TaskState`
  (@Serializable: stage, step, expectedAction, prevStage?), `TaskStateMachine`
  (таблица рёбер, `apply`/`pause`/`resume`), `TaskStateJson` (парсинг/стрип
  fenced-блока), `TaskStatePrompts` (системный блок состояния для промпта).
- `Session`: новое поле `taskState: TaskState? = null` (default для
  back-compat); `SessionStore`: `updateTaskState`/`getTaskState` (InMemory +
  File).
- Контракт: `ChatResponse.taskState` (Models.kt) + зеркальное поле в
  `frontend/src/api/types.ts` — синхронно в одной задаче.
- API: POST `/api/task/pause`, POST `/api/task/resume` (protected) +
  chat-команды «пауза»/«продолжить».
- `Routes.kt`: инъекция состояния в промпт (`handleAgent`) + pipeline в
  `finalizeResponse`: стрип → fresh re-read → валидация → применение → echo.
- Фронтенд: индикатор этапа в `StatusLine` + кнопка Пауза↔Продолжить (зона
  SendBar) + приём `taskState` в `applyChatResponse` + фильтр блока из
  журнала.
- QA: mock-llm расширяется режимами эмиттеров task-state-блоков (legal/illegal/
  без блока/с задержкой); тесты только на моке, ноль сети.

## Вне скоупа

- Не трогать: `/api/cancel`, `ActiveRequests`, `SessionHistory.trim`, пары
  assistant(tool_calls)→tool, `ReasoningPrompts.budgetNote`.
- Не захватывать taskState в Branch-снимки (осознанное ограничение, решение #8).
- Не добавлять конфиг-шов: FSM always-on, без тумблера.
- Не добавлять серверные автопереходы (только LLM-edge + пауза/продолжить).
- Не хранить task-state блок в истории сообщений.
- Не восстанавливать reasoning-режимы; Prompt-to-Prompt и Team не трогаются.
- Тесты без сети (только мок); никаких английских алиасов команд.
- Фронт: цвета только из `:root`/`styles/tokens.css` (DESIGN.md), без
  `as any`/`@ts-ignore`, без console.log в проде; localStorage для FSM-состояния
  не вводится (состояние живёт на серверной сессии).
- Не архивировать другие OpenSpec changes.
