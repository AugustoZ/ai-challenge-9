# Change: Доступ бота к файлам проекта (выдача файла документом)

## Зачем

Бот отвечает по документации проекта (RAG-корпус — только `*.md`), но не может
показать сам файл исходников: на вопрос «покажи, как устроена авторизация» он
перескажет документацию, а пользователь хочет получить файл кода. Хочется:
попросил файл (или «покажи, как устроено X») — бот нашёл файл в дереве проекта
и прислал его ответным сообщением как документ Telegram.

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Доступ к проекту | Новый модуль `project_files.py`: read-only, корень = `PROJECT_FILES_ROOT` (дефолт — корень ai-challenge-9) | Тот же стиль, что `deps_map.py`: чистые функции, без LLM |
| Безопасность | Нормализация пути + проверка вхождения в корень БЕЗ `resolve()`; скрип `~`, `..`; блэклист служебных каталогов (.git, node_modules, build, dist, data, .venv…) и бинарных расширений | Питфолл проекта: `resolve()` ломает сравнение родителей на симлинках `docs/ru/<repo>`; наружу путь не выпускаем |
| Прямой интент | «(покажи|пришли|скинь|отправь|дай) файл <имя>» ловится ДО RAG (`_FILE_INTENT_RE`) | Детерминированная выдача без траты токенов, по образцу deps-интента |
| LLM-сценарий | В RAG-промпт (только когда вопрос похож на «покажи/файл/как устроена») добавляется правило: последней строкой ответа — `<file>путь/от/корня</file>` | Двухфазная схема уже работает для `<doc>`; модель знает пути из AGENTS.md-дерева |
| Размытые пути | `resolve_request`: прямой путь → срез префикса корпуса `ru/<repo>/` → поиск по имени файла (`find_files` по basename) | qwen3.5 часто называет файл без полного пути — авто-коррекция по имени |
| Отправка | `_send_document` (multipart, text/plain), caption = путь в проекте; ≤2 файлов на ответ, потолок 300 000 символов на файл | Переиспользование готового канала отправки; лимит от спама |
| Не нашли файл | Явная приписка «Не нашёл файл «X» в проекте» к текстовому ответу | Отказ честный, молчание запрещено |

## Edge cases

- «Покажи файл» без имени → интент не закрывает вопрос, идём дальше через RAG.
- Прямой интент, файлов по запросу несколько → список найденных путей с просьбой уточнить.
- Прямой интент, ничего не нашли → вопрос продолжается через RAG (не отказ).
- Маркер `<file>` с несуществующим путём → приписка о неудаче, маркер из ответа вырезан.
- Бинарный файл (расширение или NUL-байты) → «не нашёл» с указанием причины-класса.
- Выход за корень (`../`) → отказ ещё на резолве пути.

## Волны

1. Модуль `project_files.py`: `project_root`, `find_files`, `read_text`, `resolve_request` — чистые функции + реальное дерево проекта.
2. Проводка в `bot_responder.py`: `_FILE_INTENT_RE` + `_send_file_intent`, правило `_FILE_FETCH_RULE` в RAG-блоке, `_take_file_requests`, отправка документов, справка `/help`.
3. Верификация: py_compile, inline-смоки (чистые функции + containment + resolve), деплой на прод-поллер, проверка лога.
