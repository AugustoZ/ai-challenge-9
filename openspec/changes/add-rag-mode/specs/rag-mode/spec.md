# Спецификация: RAG-режим (rag-mode)

## ADDED Requirements

### Requirement: RAG-режим — пре-инжекция релевантных чанков до вызова LLM

При `body.ragEnabled == true` И сконфигурированном `config.rag.url` система
MUST до вызова LLM найти релевантные чанки корпуса запросом к sidecar
(`POST /search`) и добавить в семя агентного цикла отдельное system-сообщение
с RAG-блоком (заголовок — константа RAG_MARKER «РЕЛЕВАНТНЫЕ ДОКУМЕНТЫ»,
инструкция отвечать по приведённым документам и указывать источники в виде
`[файл · раздел]`, нумерованные чанки `[N] source: <файл> · раздел: <section>`
с полным текстом чанка). Блок MUST добавляться ПОСЛЕ обрезки семени и ПОСЛЕ
блока памяти (последнее сообщение семени). Retrieval query MUST быть
последним user-сообщением. Бюджет блока — `maxBlockChars` символов
(дефолт 6000); превышение — пер-чанк обрезка с «…».

#### Scenario: Тумблер включён — RAG-блок в запросе к LLM
- **WHEN** пользователь отправляет сообщение с `ragEnabled=true`, `config.rag.url`
  сконфигурирован, sidecar вернул непустой список чанков
- **THEN** запрос к LLM содержит system-сообщение с RAG_MARKER и текстом чанков
  после сообщения пользователя; ответ несёт `ragEnabled=true` и непустой
  `retrievedSources`

#### Scenario: Тумблер выключен — инжекта нет
- **WHEN** пользователь отправляет сообщение с `ragEnabled=false` (или без поля)
- **THEN** запрос к LLM не содержит RAG-блока, обращения к sidecar нет, ответ
  несёт `retrievedSources=[]`

#### Scenario: RAG запрошен, но адрес не сконфигурирован
- **WHEN** `ragEnabled=true`, но `config.rag.url` не задан (null)
- **THEN** обращения к sidecar нет, ответ обычный, `retrievedSources=[]`

### Requirement: Fail-open — сбой sidecar не роняет ход

Сбой sidecar (недоступный адрес, таймаут, ненулевой статус, ошибка парсинга)
MUST NOT ломать ход: ответ возвращается как обычно (HTTP 200),
`retrievedSources=[]`, RAG-блок в промпт не попадает; сбой MUST логироваться
warn-логом. Пустой результат поиска (0 чанков) обрабатывается так же, как сбой
инжектом — блока в семени нет.

#### Scenario: Sidecar недоступен
- **WHEN** `ragEnabled=true`, но sidecar не запущен (порт закрыт) либо не
  ответил в пределах `timeoutMs`
- **THEN** ответ успешен (HTTP 200), текст сгенерирован в обычном режиме,
  `retrievedSources=[]`, в логах warn-запись о сбое

#### Scenario: Поиск вернул ноль чанков
- **WHEN** `ragEnabled=true`, sidecar доступен, но поиск вернул пустой список
- **THEN** запрос к LLM не содержит RAG-блока, `retrievedSources=[]`, ход
  завершается успешно

### Requirement: Источники ответа — метаданные, видимые в UI

Ответ `ChatResponse` MUST содержать в JSON поля `ragEnabled: Boolean` и
`retrievedSources: List<RetrievedSource>` ВСЕГДА (включая выключенный RAG —
ключи присутствуют в JSON). `RetrievedSource` = только метаданные: chunkId,
source, title, section, score, snippet (≤200 символов); полный content MUST NOT
включаться. В UI под ответом MUST отображаться блок «Источники» (раскрывающийся,
строки `[N] source · section · score`) и бейдж с числом источников в шапке
записи; при выключенном RAG или пустом списке блок и бейдж отсутствуют.

#### Scenario: Источники видны под ответом
- **WHEN** пользователь получает ответ с `ragEnabled=true` и тремя элементами
  `retrievedSources`
- **THEN** под ответом отображается блок «Источники» с тремя строками
  (файл · раздел · score), в шапке записи — бейдж с числом 3

#### Scenario: Ключи ответа всегда присутствуют
- **WHEN** пользователь получает ответ с `ragEnabled=false`
- **THEN** JSON ответа содержит оба ключа: `ragEnabled` (false) и
  `retrievedSources` (`[]`)

### Requirement: Контрольный набор из 10 вопросов

В репо MUST существовать файл `eval/rag-questions.yaml` — 10 контрольных
вопросов по корпусу корпус документации, у каждого: текст вопроса; ожидание —
expectedSubstrings (1–3 фрагмента, которые должны встретиться в ответе,
сравнение case-insensitive); источники — expectedSources (1–2 пути файлов, где
зафиксирован ответ). Подстрочки MUST быть проверены на вхождение в текст
корпуса; для каждого вопроса релевантный source MUST находиться в top-5 поиска.

#### Scenario: Набор валиден и полон
- **WHEN** проверяется `eval/rag-questions.yaml`
- **THEN** ровно 10 элементов, у каждого question/expectedSubstrings/
  expectedSources; каждая expectedSubstring найдена в соответствующем
  source-файле; для каждого вопроса поиск находит expectedSource в top-5

### Requirement: Харнесс сравнения RAG vs no-RAG

В репо MUST существовать скрипт `scripts/rag_eval.py`: для каждого из 10
вопросов прогонять оба режима (ragEnabled=false и ragEnabled=true) через
`POST /api/chat`, выполнять авто-проверки (все expectedSubstrings присутствуют
в ответе; expectedSources упомянуты в ответе ИЛИ в retrievedSources для
RAG-режима), собирать баллы Судьи и токены/время и формировать
markdown-отчёт-таблицу 10×2 со строкой итогов (RAG лучше/равно/хуже). Модель —
обязательный CLI-параметр. Недоступность sidecar — не ошибка, а диагностическое
сообщение в отчёте; exit code всегда 0 (report-only).

#### Scenario: Полный прогон харнесса
- **WHEN** запущены приложение, sidecar и LLM (mock или живая модель) и
  выполнена команда `python3 scripts/rag_eval.py --model <m>`
- **THEN** сформирована таблица 10×2 (вопрос | режим | проверки | источники |
  Judge | токены | время), отчёт записан в файл `--out` и продублирован в
  stdout, exit code 0

#### Scenario: Sidecar не запущен
- **WHEN** харнесс запускается при выключенном sidecar
- **THEN** соответствующие строки помечены диагностикой «sidecar не запущен»
  с подсказкой команды запуска, traceback отсутствует, exit code 0
