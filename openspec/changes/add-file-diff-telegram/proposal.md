# Change: Дифф присланных файлов против GitHub main

## Зачем

Бот не умеет сравнивать присланное с репозиторием: пользователь не может
быстро узнать, чем его версия файла отличается от того, что лежит в GitHub.
Хочется: прислал боту файлы — получил по каждому дифф против ветки `main`
и LLM-вердикт, как при получении PR.

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Триггер | Документы, присланные боту в чат | Прямо и без новых команд |
| Лимит файлов | 5 за одну отправку | По требованию пользователя; больше — вежливый отказ |
| Поиск «одноимённого» | git trees API (`recursive=1`), матч по имени файла, кеш 300 с | Имя в Telegram без пути; дерево репо маленькое |
| Откуда контент main | `GET /contents/{path}?ref=main` (raw) | Тот же приём, что в pr_review |
| Дифф | `difflib.unified_diff` локально, заголовки `---/+++` срезаются | LLM диффы не генерирует; формат как патчи GitHub |
| Вердикт | Локальная LLM (`_generate`) | Единый стиль с PR-ревью |
| Отправка | Диффы — готовым HTML (`_send_html` + `render_diff_html`), вердикт текстом | Как в pr_review |
| Пакетирование | Окно 2 с на чат (документы приходят по одному) | «Более 5 за раз» детектируется только пакетом |
| Куда отвечает | В тот же чат, откуда файлы | Естественный диалог |
| Реф | `main`, override `FILEDIFF_REF` | Дефолт по требованию |

## Edge cases

- Файла с таким именем нет в main → явное сообщение, вердикт не строится по нему.
- Несколько одноимённых файлов → берётся кратчайший путь, путь показывается в выводе.
- Бинарный файл (NUL-байты) → «дифф недоступен», вердикт без диффа.
- Файл идентичен main → «совпадает с main», в промпт не попадает.
- Нет GitHub-токена → сообщение об ошибке, падения нет.
- Документ с подписью → подпись идёт комментарием, текстовый роутинг пропускается.

## Волны

1. Модуль `file_diff.py`: чистые функции (матч путей, дифф, промпт) + оркестрация.
2. Проводка в `bot_responder.py`: приём документов, батч, `Job.documents`, скачивание файла, хендлер, справка.
3. Верификация: py_compile, inline-смоки чистых функций, живой прогон против GitHub (read-only), деплой на прод-поллер, проверка лога.
