# Spec: Дифф присланных файлов против GitHub main (Telegram)

## ADDED Requirements

### Requirement: Приём файлов-запросов
Бот ДОЛЖЕН принимать присланные документы (1–5) как запрос на сравнение с
веткой `main` репозитория из секции `github` config.json.

#### Scenario: Пакет файлов
- **WHEN** пользователь присылает 3 файла подряд в течение окна 2 с
- **THEN** бот обрабатывает их одним пакетом и отвечает по каждому файлу

#### Scenario: Превышение лимита
- **WHEN** в пакете более 5 файлов
- **THEN** бот отвечает «Пожалуйста, отправьте не более 5 файлов за раз.»
  и не вызывает LLM

### Requirement: Сравнение с main
Для каждого файла бот ДОЛЖЕН найти одноимённый файл в дереве `main`
(матч по имени, кеш дерева 300 с), скачать его содержимое и вычислить
unified-дифф локально.

#### Scenario: Одноимённый файл найден
- **WHEN** в дереве `main` есть файл с тем же именем
- **THEN** бот отправляет дифф (HTML-подсветка как в PR-ревью) с указанием
  полного пути найденного файла

#### Scenario: Файл не найден
- **WHEN** одноимённого файла в `main` нет
- **THEN** бот сообщает об этом по данному файлу и продолжает по остальным

#### Scenario: Файлы идентичны
- **WHEN** присланный файл байт-в-байт совпадает с версией `main`
- **THEN** бот сообщает «совпадает с main», дифф не отправляется

### Requirement: Вердикт LLM
После отправки диффов бот ДОЛЖЕН запросить у локальной LLM вердикт
(Резюме / Проблемы / Вердикт «ОК» или «Требует правок») и отправить его
в тот же чат.

#### Scenario: Вердикт
- **WHEN** диффы отправлены
- **THEN** ответ LLM уходит в чат отправителя с пометкой ветки сравнения

### Requirement: Ответ в чате отправителя
Результаты ДОЛЖНЫ уходить в чат, откуда пришли файлы, а не админам.

#### Scenario: Личный чат
- **WHEN** файлы присланы в личный чат
- **THEN** диффы и вердикт отправлены в этот же чат
