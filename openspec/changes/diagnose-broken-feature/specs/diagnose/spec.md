# Spec: Диагностика «почему не работает X» (Telegram)

## ADDED Requirements

### Requirement: Поиск существующих issue
Бот ДОЛЖЕН при вопросе вида «почему не работает X» искать issue по теме X
(Search API GitHub) в репозиториях секции `github` config.json.

#### Scenario: Issue найден
- **WHEN** в выдаче поиска есть issue с пересечением стемов темы и
  названия/тела
- **THEN** бот отвечает списком «#N «название» (открыт/закрыт) — ссылка»
  и вопрос закрывается без LLM

#### Scenario: Issue не найден
- **WHEN** выдача пуста или ни один хит не пересекается с темой
- **THEN** бот переходит к RAG-вердикту по той же теме

### Requirement: RAG-вердикт при отсутствии issue
Если issue не найдены, бот ДОЛЖЕН выполнить RAG-поиск по вопросу, передать
найденные чанки документации локальной LLM и отправить вердикт в формате
«Вердикт / Проверить».

#### Scenario: Вердикт
- **WHEN** RAG вернул чанки
- **THEN** ответ LLM уходит в чат отправителя с указанием источников

#### Scenario: RAG недоступен или пуст
- **WHEN** sidecar поиска недоступен или не вернул чанков
- **THEN** бот отвечает обычным plain-фолбэком без падения

### Requirement: Добор локальных файлов в промпт
Если модели не хватает данных, она МОЖЕТ запросить файл маркером
`<file>путь</file>`; бот ДОЛЖЕН прочитать файл из дерева проекта
(`project_files`), добавить содержимое в промпт и перегенерировать вердикт.

#### Scenario: Файл запрошен и найден
- **WHEN** модель вывела `<file>путь</file>` и файл существует в дереве проекта
- **THEN** содержимое файла уходит в промпт, вердикт перегенерируется
  (файл не отправляется в чат)

#### Scenario: Файл не найден
- **WHEN** путь не резолвится или файл бинарный/нечитаемый
- **THEN** отправляется вердикт первой фазы

### Requirement: Деградация без смерти запроса
С RAG НЕ ДОЛЖНЫ оставлять вопрос без ответа.

#### Scenario: GitHub недоступен
- **WHEN** Search API вернул ошибку сети или HTTP 4xx/5xx
- **THEN** в логе warning, обработка продолжается RAG-вердиктом
