# Change: Диагностика «почему не работает X» (issue GitHub → RAG-вердикт)

## Зачем

Бот не отвечает на главный диагностический вопрос «почему не работает …»:
обычный RAG-ответ не знает про баг-трекинг и не строит гипотезу причины.
Хочется: спросил боту «почему не работает X» — получил либо ссылку на уже
созданный issue в репозитории проекта (с названием), либо анализ документации
проекта локLM с предполагаемым вердиктом о причине.

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Триггер | Регэксп интента «почему (не) работает/запускается/падает/ошибка …» в `_handle_ask` до RAG | Без новых команд; узкий шаблон не перехватывает обычные вопросы |
| Поиск issue | GitHub Search API (`GET /search/issues`, `repo:… is:issue`), read-only | Тот же токен/репо из секции `github`, что у /create и filediff |
| Фильтр выдачи | Пересечение стемов темы с title/body (≥1), топ-3, открытые раньше закрытых | Search API возвращает слабо релевантные хиты — отсекаем |
| Найдено | Список «#N «название» (открыт/закрыт) — ссылка», запрос закрывается | Прямое требование пользователя |
| Не найдено / GitHub недоступен | RAG-поиск по теме + вердикт LLM | Деградация без смерти запроса |
| Вердикт | Чанки RAG в system-блок + формат «Вердикт / Проверить», промпт с `/no_think` | Единый стиль с RAG-ответами; причины не выдумывать |
| Локальные файлы | Маркер `<file>путь</file>` → `project_files` читает файл → блок в промпт → перегенерация | Содержимое файла идёт В LLM (анализ), а не в чат |
| Модуль | `diagnose.py` (чистые функции + один сетевой вызов), проводка в `bot_responder.py` | В стиле file_diff.py / deps_map.py |
| История | Найденные issue и вердикт пишутся в `_remember_turn` | Уточняющие вопросы модели по ходу беседы |

## Edge cases

- Нет токена/репо в секции `github` → поиск issue пропускается, сразу RAG-вердикт.
- GitHub недоступен / 4xx-5xx → warning в лог, RAG-фолбэк.
- Search API вернул слабые хиты (0 пересечений стемов) → считается «не найдено».
- RAG недоступен или пуст → `_handle_plain` (как в обычном ask).
- LLM запросила файл, но он не резолвится → ответ без добор-блока (первая фаза).
- Второй `<file>`-маркер в перегенерации → срезается, файлов не присылается.

## Волны

1. Модуль `diagnose.py`: extract_topic, pick_issues, format_issues, files_block,
   search_issues, DIAGNOSE_SYSTEM.
2. Проводка в `bot_responder.py`: `_DIAGNOSE_INTENT_RE`, `_handle_diagnose`,
   параметр `system` в `_build_rag_block`, строка в `/help`.
3. Верификация: py_compile, inline-смоки чистых функций, живой read-only прогон
   Search API, деплой на прод-поллер, проверка лога.
