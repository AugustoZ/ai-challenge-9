# Change: Шелл в мини-агенте + агент по умолчанию

## Зачем

Бот на императивы вида «сделай в проекте новую ветку lesson_35_ver2»
отвечал как RAG-справочник («я отвечаю только по документам»): свободный
текст в личке всегда уходит в `ask` (bot_responder.py:531), агентный режим
доступен только по явному `/agent`. Кроме того, агентному циклу не хватает
шелла: он не может ни создать git-ветку, ни прогнать тесты и увидеть ошибки
(а значит — не может довести правку до зелёного состояния).

Две доработки:

1. **Шелл-тул в агентном цикле** — новый маркер `<shell>команда</shell>`:
   агент запускает команды в корне проекта (тесты, git-ветки, py_compile),
   видит вывод и продолжает работу.
2. **Агент по умолчанию** — свободный текст в личке маршрутизируется
   LLM-классификатором: вопрос по документации/проекту → RAG, всё
   остальное → агентная сессия. `/agent` и `/ask` остаются явными
   переключателями.

## Ключевые решения

| Решение | Выбор |
|---|---|
| Маркер шелла | `<shell>команда</shell>` — тег С телом (как write/patch); незакрытый `<shell>` отбрасывается целиком (питфолл qwen с незакрытыми тегами уже решён для read — shell в него не входит) |
| Исполнение | `subprocess` без `shell=True`, `shlex.split`, cwd = корень проекта (PROJECT_FILES_ROOT), таймаут 120 с, вывод в контекст LLM ≤4000 символов, каждая команда — в `log_step` и отчёт |
| Безопасность — белый список | Список разрешённых команд — config.json `agent.shell_allow` (дефолт: `git status/log/diff/branch/checkout/switch`, `ls`, `grep`, `npm test`, `npm run`, `./gradlew test`, `python -m py_compile`); совпал — команда исполняется сразу, вывод возвращается модели |
| Безопасность — гейт | Команды вне белого списка (в т.ч. с шелл-метасимволами `| && ; >` — их нельзя верифицировать по первому токену) копятся в сессии `pending_commands` и исполняются ТОЛЬКО после «применяй» в `_handle_agent_confirm`, вместе с записью правок |
| Запреты | `git commit/push` запрещены всегда (правило «агент не коммитит»), отказ без постановки в гейт. Аргументы-пути `config.json`/`.env` в любой команде — отказ: белый список не должен становиться каналом утечки секретов (`grep key config.json`) в контекст LLM и чат |
| Маршрутизация | Свободный текст в личке → `_llm_is_project_doc_question` (ДА/НЕТ, max_tokens 8, `/no_think`, сбой транспорта/пустой ответ → RAG): ДА → `ask` (RAG как сейчас), НЕТ → запуск агентной сессии (клавиатура модели → цикл) |
| Порядок защиты | deps-интент, файл-интент и create-интент проверяются ДО классификатора (без-LLM пути не должны платить за классификацию); активная сессия агента перехватывает текст как раньше (`agent_note`/`agent_confirm`) |
| Явные команды | `/agent <задача>` — принудительно агент; `/ask <вопрос>` — принудительно RAG; группы не тронуты (RAG по упоминанию) |
| Лимиты цикла | `_AGENT_MAX_ITERATIONS = 5` не меняем; вывод шелла возвращается в следующей итерации тем же блоком, что и файлы чтения |

## Edge cases

- **Незакрытый `<shell>`** — отбрасывается целиком; qwen пишет теги без
  закрытия (наблюдено), read-исключение на shell НЕ распространяется.
- **Метасимволы** (`| && ; >`) — автоматом не исполняются: белый список
  матчится по первому токену каждой части, составная команда уходит в гейт.
- **Таймаут/обрыв** — в контекст возвращается «команда превысила таймаут»,
  цикл продолжается; процесс убивается.
- **Классификатор** — reasoning-модели (glm/deepseek) с max_tokens 8
  возвращают пустой content (бюджет уходит в reasoning) → пустой/неразобранный
  ответ = «вопрос» → RAG (безопасный фолбэк, старое поведение).
- **Дегенерация 9b в цикле с шеллом** — смягчается белым списком:
  худший случай — зацикленные `git status`, ограничено 5 итерациями.
- **Сессия агента активна** — новый свободный текст дополняет задачу или
  попадает в гейт, классификатор не вызывается (как сейчас).
- **Без каталога agent.models** — классификатор не вызывается, бот
  работает по-старому (RAG на всё).
- **cd в команде** — бессмысленен: каждая команда стартует в корне проекта;
  относительные пути валидны от корня.

## Волны

1. **Волна 1 — шелл**: `project_shell.py` (белый список, разбор, исполнение),
   маркер `<shell>` в `agent_session.parse_markers`, проводка в
   `_handle_agent_run` (allow → сразу, остальное → `pending_commands`),
   исполнение pending в `_handle_agent_confirm`, AGENT_SYSTEM.
2. **Волна 2 — агент по умолчанию**: классификатор, проводка в
   `_route_message` (после без-LLM интентов), `/ask` в справке,
   `_WELCOME`/`_HELP`.
3. **Волна 3 — верификация и деплой**: смоки чистых функций (белый список,
   парсер, классификатор на стабах), рестарт поллера по процедуре, живой
   прогон («создай ветку» → агент, «почему не работает X» → RAG), скилл.
