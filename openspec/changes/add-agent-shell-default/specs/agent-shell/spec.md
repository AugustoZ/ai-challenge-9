# Spec: Шелл-тул мини-агента

## ADDED Requirements

### Requirement: Шелл-маркер в агентном цикле
Агентный цикл ДОЛЖЕН поддерживать маркер `<shell>команда</shell>` (тег
с телом): команда исполняется в корне проекта, её вывод (обрезанный до
4000 символов) и код возврата возвращаются модели в следующей итерации.
Незакрытый тег `<shell>` ДОЛЖЕН отбрасываться целиком (без исключения
«read без тела»).

#### Scenario: Запуск тестов
- **WHEN** агент вернул `<shell>npm test</shell>` в итерации
- **THEN** команда исполнена в корне проекта, вывод — в контексте
  следующей итерации, шаг записан в `log_step`

#### Scenario: Незакрытый тег
- **WHEN** модель вернула `<shell>git status` без `</shell>`
- **THEN** маркер отброшен целиком, цикл продолжается

### Requirement: Белый список и гейт
Команды из белого списка (config.json `agent.shell_allow`, дефолт:
`git status/log/diff/branch/checkout/switch`, `ls`, `grep`, `npm test`,
`npm run`, `./gradlew test`, `python -m py_compile`) ДОЛЖНЫ исполняться
сразу. Команды вне списка и команды с шелл-метасимволами (`|`, `&&`, `;`,
`>`) ДОЛЖНЫ копиться в сессии (`pending_commands`) и исполняться только
после подтверждения «применяй» в гейте, вместе с записью правок.
`git commit` и `git push` ДОЛЖНЫ отвергаться всегда, без постановки в гейт.

#### Scenario: Разрешённая команда
- **WHEN** агент запросил `git branch feature-x`
- **THEN** команда исполнена немедленно, вывод — модели

#### Scenario: Команда вне списка
- **WHEN** агент запросил `rm -rf build`
- **THEN** команда попала в `pending_commands`, пользователю показана в
  списке к подтверждению, исполнена только после «применяй»

#### Scenario: Составная команда
- **WHEN** агент запросил `npm test && git status`
- **THEN** команда не исполняется автоматически (метасимволы) — в гейт

#### Scenario: Запрещённая навсегда
- **WHEN** агент запросил `git push origin main`
- **THEN** отказ с пояснением «агент не делает commit/push», в гейт не
  попадает

#### Scenario: Отмена в гейте
- **WHEN** пользователь ответил «отмена» при непустом `pending_commands`
- **THEN** ни одна команда не исполнена, сессия сброшена

### Requirement: Ограничения исполнения
Исполнение ДОЛЖНО быть: без `shell=True` (разбор `shlex.split`), cwd —
корень проекта на каждый запуск, таймаут 120 с с убийством процесса,
кап вывода 4000 символов. Команда и её вывод ДОЛЖНЫ попадать в `log_step`
и финальный отчёт. Команды с аргументами-путями `config.json`/`.env`
ДОЛЖНЫ отвергаться (белый список не канал утечки секретов).

#### Scenario: Аргумент — секрет
- **WHEN** агент запросил `grep apiKey config.json`
- **THEN** отказ с пояснением, секрет в контекст LLM и чат не попадает

#### Scenario: Таймаут
- **WHEN** команда не завершилась за 120 с
- **THEN** процесс убит, модель получила «команда превысила таймаут»,
  цикл продолжается

#### Scenario: Отчёт
- **WHEN** агент завершил задачу с исполненными командами
- **THEN** в отчёте перечислены команды и исходы (успех/таймаут/отказ)
