# Спецификация: github-pr-watcher

## ADDED Requirements

### Requirement: Уведомление о создании PR

Бот SHALL опрашивать открытые PR настроенных репозиториев GitHub не реже
чем раз в 60 c (по умолчанию 30 c) и SHALL отправлять уведомление в
настроенные чаты Telegram при появлении PR, отсутствующего в хранилище.

#### Scenario: Новый PR

- **WHEN** ответ API содержит PR с `(repo, number)`, которого нет в таблице `github_prs`
- **THEN** бот записывает PR в БД и отправляет в чаты сообщение с номером, названием, автором, веткой и ссылкой

#### Scenario: Рестарт бота

- **WHEN** бот перезапускается и опрашивает API впервые
- **THEN** все открытые на момент старта PR фиксируются в БД без уведомления (baseline)

### Requirement: Контекст PR для LLM

Бот SHALL предоставлять локальной LLM список открытых PR (номер, название,
автор, дата) как служебный блок system-промпта обычных (не-RAG) ответов.

#### Scenario: Вопрос про PR

- **WHEN** пользователь спрашивает «что за PR?» и в хранилище есть открытые PR
- **THEN** блок контекста содержит их перечень, и модель отвечает, опираясь на него, не выдумывая номера

#### Scenario: PR отсутствуют

- **WHEN** список открытых PR пуст
- **THEN** блок контекста не добавляется в промпт

### Requirement: Отказоустойчивость наблюдателя

Наблюдатель SHALL продолжать работу при недоступности GitHub API и SHALL
НЕ влиять на обработку сообщений бота.

#### Scenario: GitHub недоступен

- **WHEN** запрос к API завершился ошибкой сети/HTTP
- **THEN** наблюдатель повторяет попытку после экспоненциального бэкоффа (до 5 мин), логирует причину и не падает

#### Scenario: Наблюдатель не настроен

- **WHEN** токен или список репозиториев не заданы
- **THEN** наблюдатель завершается с INFO-логом, бот работает как раньше
