# Изменение: GitHub PR-наблюдатель — уведомления о создании PR

> Статус: implemented. Capabilities: github-pr-watcher.
> Реализация — в standalone-боте `shturman-bot` (модуль `github_watcher.py`),
> здесь — архитектурная запись по конвенции openspec.

## Задание

Бот «Штурман» и локальная LLM должны узнавать о создании PR на GitHub:
бот сам сообщает о новом PR в чат Telegram, а список открытых PR доступен
модели как контекст при ответах на вопросы.

## Зачем

Раньше о новом PR можно было узнать, только проверяя GitHub вручную.
У бота уже есть долгоживущий процесс, Telegram-доставка и хранилище —
не хватало только источника событий. Вебхуки отклонены: бот живёт на Mac
за NAT, публичный HTTPS-эндпоинт потребовал бы туннеля/релея ради редкого
события. Выбран опрос API (вариант C из `add-pr-review-pipeline` — как
запасной поднят в основной): частота 30 c, дедуп в SQLite, нулевая
инфраструктура.

## Ключевые решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | Опрос `GET /repos/{repo}/pulls?state=open&sort=created` раз в 30 c вместо вебхуков | Mac за NAT; события редкие; PAT уже в `config.json` |
| 2 | Новый модуль `github_watcher.py` внутри `bot_responder.py`-процесса (asyncio-таск), не отдельный сервис | Одна точка отправки Telegram; правило одного getUpdates-поллера не задевается |
| 3 | Конфиг — секция `github` в `config.json` (`token/repos/chats/interval_sec`), env-override `GH_*` | Конвенция секретов; контейнер монтирует config `:ro` |
| 4 | Дедуп — таблица `github_prs` в общей БД (`TgStore`), ключ `(repo, number)` | Переживает рестарт; история доступна для отладки |
| 5 | Первый проход — baseline: открытые PR фиксируются без уведомления | Рестарт бота не спамит старыми PR |
| 6 | Контекст для LLM — in-memory список недавних PR, инжектится в system plain-ответов (`_handle_plain`) | LLM отвечает на «что за PR?» без выдуманных номеров; RAG-путь (прошивки) не засоряем |
| 7 | Уведомление — markdown-ссылка через существующий `_md_to_telegram_html` | Нет нового кода форматирования |

## Edge cases

- Токен/repos не заданы → наблюдатель выключается с INFO-логом, бот живёт как раньше.
- GitHub 4xx/5xx/таймаут → экспоненциальный бэкофф (до 5 мин), цикл не падает.
- Ошибка отправки в чат → лог + продолжение (остальные чаты получают).
- PR закрыт между опросами → уведомления не будет (ограничение поллера, задокументировано).
- Некорректная запись в ответе API → пропускается с warning.
