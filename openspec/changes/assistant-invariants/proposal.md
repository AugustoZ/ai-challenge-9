# Изменение: Инварианты ассистента

> Статус: draft. Capabilities: `assistant-invariants`.
> SDD-фиксация доработки; реализация идёт по `tasks.md` этого change.

## Зачем

Ассистент «Штурман» отвечает в рамках своих общих промптов, но не знает о
правилах, которые пользователь или команда обязаны соблюдать: выбранная
архитектура, принятые технические решения, ограничения стека, бизнес-правила.
Единственный способ удержать ассистента в рамках — напоминать правило в каждом
новом запросе, и в длинном диалоге оно тонет в истории.

Change вводит инварианты — правила, которые ассистент не имеет права нарушать.
Они хранятся отдельно от диалога: глобальные (файл, видны всем сессиям и всем
пользователям) и сессионные (поле сессии, живут на время сессии). Каждый ход
сервер подставляет блок инвариантов с инструкцией отказа в system-промпт
(4-й tail-слот seed: предпочтения → состояние задачи → инварианты → память),
и модель видит правила при каждом ответе. Источник — гибрид: панель настроек
управляет обоими скоупами, команды в чате — сессионным. Отказ —
промпт-инструкция, без серверной механики блокировки: модель отказывается
сама, называя нарушенный инвариант и объясняя причину. Change не зависит от
конечного автомата задачи: этапы, шаги и переходы не затрагиваются.

## Ключевые решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | **Гибридный источник**: отдельная секция «Инварианты» в SettingsPanel (список, добавление, удаление, оба скоупа) + 3 chat-команды (только session-scope) | Панель даёт управляемость и видимость, команды — способ задать правило на лету, не уходя из чата; обе половины повторяют существующие паттерны (секции настроек, pre-LLM-команды) |
| 2 | **Гибридный скоуп**: глобальные (файл `<dataDir>/invariants.json`, действуют во всех сессиях всех пользователей) + сессионные (поле `Session.invariants`, живут на время сессии) | Команде нужны постоянные правила (стек, архитектура), отдельной сессии — временные уточнения; «глобальные» осознанно связывают всех пользователей |
| 3 | **Форма `StoredInvariant(id: String, text: String)`**, `id` = UUID, создаётся при добавлении | Стабильные id дают адресное удаление (DELETE по id, панель); список строк без id не позволял бы снять неоднозначность «убери N» |
| 4 | **Глобальный стор — клон `PreferencesStore`** (минус per-user путь): один JSON-файл `{"invariants":[…]}`, atomic write (tmp + ATOMIC_MOVE), missing/corrupt → пустой дефолт (не исключение), свой `Json { ignoreUnknownKeys = true }`, `@Synchronized`-мутации, traversal-гварды | Доказанный паттерн стора в репозитории; клонирование, а не DRY-слияние — конвенция репо (G4) |
| 5 | **`Session.invariants` — клон рецепта сессионного поля**: `val invariants: List<StoredInvariant> = emptyList()` + `updateInvariants`/`getInvariants` в обоих сторах; legacy-файл без поля читается с emptyList (дефолт поля — back-compat, `ignoreUnknownKeys` — rollback; нужны оба) | Нет нового хранилища: инварианты живут и умирают с сессией; старые файлы на диске продолжают читаться |
| 6 | **Инъекция 4-м tail-слотом seed `handleAgent`**: порядок предпочтения → состояние задачи → инварианты → память; позиция ПОСЛЕ trim; саб-вызовам (экстрактор/сводка/судья) блок не передаётся; комментарий порядка в `Routes.kt` — документированный контракт, обновляется вместе с кодом | Эфемерная system-строка: правила видны каждый ход без разрастания истории; фиксированный порядок + приоритет упаковки trimContext (свежие группы первыми) защищают блок от контекстного давления; контракт задокументирован |
| 7 | **Промпт-отказ**: маркер-заголовок `НЕПРЕЛОЖНЫЕ ИНВАРИАНТЫ (нарушать запрещено)` + константа `REFUSAL_INSTRUCTION` (отказаться, назвать инвариант, объяснить причину); секции «Глобальные:»/«Сессия:»; кап блока ~2000 символов, переполнение → эллипсис; пустой блок НЕ инъектируется | Согласованный механизм: промпт-инструкция, не механика (G3); маркер — стабильный контракт для мок-режима refuse и для тестов |
| 8 | **Команды**: exact «инварианты»/«/инварианты» проверяется ПЕРВЫМ; префиксы «инвариант »/«/инвариант » (добавить) и «убери инвариант »/«/убери инвариант » (удалить по 1-based номеру, только цифры); только с начала сообщения; без вызова LLM; поведение истории — точное зеркало существующего pre-LLM обработчика команд; ответы команд несут echo | Exact-first, чтобы prefix «инвариант » не глотал слово «инварианты»; пробел в префиксе пропускает обычную речь («инвариантность важна»); нумерация только в session-scope — глобальные управляются панелью (пометка в списке) |
| 9 | **API: 5 защищённых роутов** (контракт в таблице ниже); все — в таблице защищённых маршрутов и в `AuthInterceptTest` (включая garbage-token representatives) | Отдельный контракт от `/api/chat`: панели нужен синхронный CRUD без ожидания хода чата |
| 10 | **Echo `ChatResponse.invariants: InvariantsPayload?`** — `{global, session}`, null когда оба скоупа пусты; через ВСЕ data-bearing места конструирования ответа (обычные и командные) | Фронт обновляет панель каждым ходом без доп. запроса: командный и обычный ответы приносят актуальное состояние |
| 11 | **Валидация**: текст 1..300 символов после trim, ≤ 20 инвариантов на скоуп, точный дубль текста после trim отклонён; всё отклонение → 400 (API) / системное сообщение (команда) | Капы защищают промпт (кап блока ~2000); дубли и мусор отклоняются на уровне стора, а не в роутах |
| 12 | **Mock-режимы `refuse` / `violate` / `echo-system`** в mock-llm.py | Детерминированный e2e без реальной модели: refuse = отказ с цитированием, ЕСЛИ маркер в system, иначе обычный ответ (тест самой инъекции); violate = безусловное нарушение (тест отсутствия блокировки); echo-system = dump полученных system |
| 13 | **UI**: секция в SettingsPanel между блоком «Память» и PreferencesSection; цвета только `var(--token)` | Канон секций (panelSection/sectionCaption, fetch-on-open по образцу PreferencesSection); без новых дизайн-токенов |

### Контракт 5 API-роутов (решение #9)

| Роут | 200 | 400 | 404 |
|---|---|---|---|
| `GET /api/invariants?sessionId={id}` | `{global, session}` | нет параметра `sessionId` | неизвестная сессия |
| `POST /api/invariants/global`, body `{text}` | `{global}` — обновлённый список | пустой/whitespace-текст; > 300 символов; точный дубль; 21-й | — |
| `DELETE /api/invariants/global/{id}` | `{global}` — обновлённый список | — | неизвестный id |
| `POST /api/invariants/session`, body `{sessionId, text}` | `{session}` — обновлённый список | то же, что выше; нет `sessionId` | неизвестная сессия |
| `DELETE /api/invariants/session/{sessionId}/{id}` | `{session}` — обновлённый список | — | неизвестная сессия или id |

Все роуты: **401** без валидного токена (включая garbage-токены). Формат
ошибок — как в существующих роутах: `{"error": "…"}`, текст на русском.

## Edge cases

- **Пустые скоупы.** Оба списка пусты → блока в промпте нет вовсе (нет
  пустой system-строки), `ChatResponse.invariants` = null.
- **Corrupt/missing глобальный файл.** Не-разбираемый файл читается как
  пустой список: без исключения наружу; следующий `add` работает, файл
  перезаписан валидным JSON.
- **Legacy-файл сессии.** Файл без поля `invariants` читается с emptyList
  (дефолт поля); запись добавляет поле, `ignoreUnknownKeys` страхует
  rollback на старую версию кода.
- **Exact «инварианты».** Проверяется ДО префикса «инвариант »: команда
  списка не превращается в «добавь пустой инвариант».
- **Команда в середине сообщения.** «объясни, что такое инварианты» → LLM:
  перехват только с начала сообщения.
- **Номер вне диапазона / не число.** «убери инвариант 99», «убери
  инвариант абв» → мягкий системный ответ (200) с примером, не ошибка.
- **21-й инвариант, 301 символ, дубль.** Стор отклоняет: API → 400, команда
  → системное сообщение с причиной.
- **Давление контекста.** Блок живёт при длинной истории: trimContext
  пачкует свежие группы первыми, tail-блоки падают только если блок сам
  превышает бюджет (тест).
- **Переполнение блока.** Кап ~2000 символов: переполнение → эллипсис по
  образцу PromptBlock.
- **Глобальные связывают всех.** Инвариант, добавленный одним пользователем,
  действует в сессиях всех пользователей (осознанное следствие выбора
  «глобальные»).
- **Ветки.** Снимок ветки (Branch) инварианты не содержит, как и состояние
  (общее на сессию); `activeDiverged()` не тронут (G6).

## Ограничения (G/E/Q)

> Номера — стабильные якоря: код и тесты задач 2–10 ссылаются на них из
> change-документов.

### Глобальные (G)

- **G1** Не трогать: `AgentLoop.kt`, `SessionHistory`, `ReasoningPrompts`,
  `JudgePrompts`, `FactPrompts`, компрессор, `Sse.kt`.
- **G2** Не инъектировать в саб-вызовы (экстрактор/сводка/судья); не
  «чинить» судью, не видящего инварианты.
- **G3** Не добавлять judge-пост-валидацию, жёсткую бэкенд-механику
  отклонения, детекцию/маркировку отказов.
- **G4** Не DRY-сливать пламбинг инвариантов с пламбингом состояния задачи —
  клонировать по конвенции репо.
- **G5** Не делать edit-in-place, категории, приоритеты, тумблеры,
  пермиссии, импорт/экспорт.
- **G6** Не включать инварианты в Branch-снимки и `activeDiverged()`.
- **G7** Не добавлять localStorage-настройки инвариантов, новую
  тест-инфраструктуру, коммиты.
- **G8** Не инъектировать пустой блок: нет инвариантов → нет
  system-строки.
- **G9** Не менять другие OpenSpec changes и specs; этот change —
  самостоятельный, переписанный с нуля.
- **G10** Позиция инъекции — ПОСЛЕ `SessionHistory.trim`, слот не
  перемещается; комментарий порядка в `handleAgent` — документированный
  контракт (Q5).

### Краевые (E)

- **E1** Missing/corrupt глобальный файл → пустой дефолт, без исключения.
- **E2** Legacy-файл сессии без поля → emptyList (дефолт поля +
  `ignoreUnknownKeys` — оба механизма).
- **E3** Точный дубль текста после trim → отклонение (400 / командное
  сообщение).
- **E4** Капы: текст 1..300 после trim, ≤ 20 на скоуп; превышение → 400 /
  командное сообщение.
- **E5** GET без `sessionId` → 400; неизвестная сессия → 404; неизвестный id
  в DELETE → 404.
- **E6** Exact «инварианты» проверяется ДО префикса «инвариант ».
- **E7** Перехват только с начала сообщения; команда в середине уходит в
  LLM.
- **E8** «убери инвариант N» без номера/вне диапазона → мягкий системный
  ответ, 200.
- **E9** Блок выживает при давлении контекста (приоритет упаковки
  trimContext; тест).
- **E10** Кап блока ~2000 символов; переполнение → эллипсис.
- **E11** Снимок ветки не содержит инвариантов.
- **E12** Глобальные инварианты действуют во всех сессиях всех
  пользователей.

### Качество (Q)

- **Q1** CI-бар — механический: инъекция + константа `REFUSAL_INSTRUCTION`
  + trim + passthrough (нарушающий ответ проходит насквозь, без блокировки).
- **Q2** Качество отказа — non-CI rubric-проверка (процедура ниже); НЕ
  acceptance-критерий задач.
- **Q3** Тесты только на моках, ноль сети (FakeLLMClient / mock-llm).
- **Q4** Фронтенд: цвета только `var(--token)` (tokens.css).
- **Q5** Комментарий порядка в `handleAgent` (предпочтения → состояние →
  инварианты → память) обновляется в задаче, как часть контракта.
- **Q6** E2E на моке: echo-system показывает инварианты в system; refuse —
  отказ при блоке и обычный ответ без него; violate — проходит без
  блокировки.

## Ручная проверка качества отказа (non-CI)

> Rubric-процедура (Q2). Выполняется вручную после финальной волны; НЕ
> acceptance-критерий ни одной задачи.

**Setup.** Глобальный инвариант: «Не предлагать jQuery». Запрос в чат: «как
подключить jQuery к проекту?»

**Ожидается.** Ассистент отказывается, называет нарушенный инвариант
(«Не предлагать jQuery») и кратко объясняет, почему запрос ему противоречит.
Может предложить совместимую альтернативу.

**Fail-примеры.** Ответ с предложением jQuery без упоминания инварианта;
отказ без названия инварианта; отказ на запрос, инварианты не нарушающий.

## Что меняется (сводка)

- Новый пакет `com.example.aiweb.invariants`: `StoredInvariant`
  (@Serializable: id, text; фабрика `create`, `normalizeAndValidate`, капы
  MAX_TEXT = 300 / MAX_COUNT = 20), `GlobalInvariantStore` (файловый стор,
  клон PreferencesStore), `InvariantPrompts` (маркер,
  `REFUSAL_INSTRUCTION`, `renderInvariantBlock`).
- `Session`: новое поле `invariants: List<StoredInvariant> = emptyList()`;
  `SessionStore`: `updateInvariants`/`getInvariants` (InMemory + File); KDoc
  на Branch дополнен.
- Контракт: `InvariantsPayload` + `ChatResponse.invariants` (Models.kt) +
  зеркало `Invariant`/`InvariantsPayload` в `frontend/src/api/types.ts` —
  синхронно в одной задаче.
- API: 5 защищённых роутов `/api/invariants…` (контракт выше).
- Chat: 3 команды до LLM («инвариант …» / «инварианты» / «убери инвариант
  N», session-scope).
- `Routes.kt`: инъекция блока в seed `handleAgent` (4-й слот) + обновление
  комментария порядка (Q5).
- Фронтенд: секция «Инварианты» в `SettingsPanel` + `useInvariants` +
  блок client.ts + echo в `applyChatResponse`.
- QA: mock-llm-режимы refuse/violate/echo-system; тесты только на моках,
  ноль сети (Q3).

## Вне скоупа

- Judge-пост-валидация, жёсткая бэкенд-механика отклонения, детекция и
  маркировка отказов (G3).
- Конечный автомат задачи (FSM): вне скоупа change — автомат, его состояние
  и его спека не меняются; инварианты — самостоятельная capability.
- Инварианты в Branch-снимках и `activeDiverged()` (G6).
- Edit-in-place, категории, приоритеты, тумблеры, пермиссии, импорт/экспорт
  (G5).
- localStorage-настройки инвариантов, новая тест-инфраструктура, коммиты
  (G7).
- Инъекция пустого блока (G8).
- Английские алиасы команд; отправка инвариантов с клиентом в
  ChatRequest (инварианты живут только на сервере).
- Архивирование других OpenSpec changes, правка других specs (G9).
