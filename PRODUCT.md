# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Kotlin/Ktor сервер, отдающий прод-сборку фронтенда: React 18 + Vite + TypeScript, Zustand-сторы, CSS Modules, marked + highlight.js из npm. Существующий код — единственный источник стека.

## Users

Несколько операторов, у каждого — свой вход, свои данные и свой стиль ответов модели. Основной пользователь — разработчик (владелец проекта): работает вечером, в тёмной комнате, за Mac, использует приложение как личную лабораторию для общения с LLM через OpenAI-совместимый API (deepseek-v4-flash на собственном gpustack-инстансе) и для экспериментов со способами рассуждения. Остальные пользователи (семья, коллеги) пользуются той же консолью, но каждый говорит с моделью по-своему: своё имя, свой ПИН, свои предпочтения, свои сессии и память. Раньше приложение было однопользовательским; legacy-данные при этом унаследовал пользователь «Шумахер» (одноразовая идемпотентная миграция при старте).

## Product Purpose

Локальный веб-клиент к LLM: отправить запрос — получить ответ. Уникальный механизм — агентная обработка: модель сама разбивает задачу на шаги, пользуется инструментами и показывает ход работы. Успех — быстрая проверка гипотез о поведении модели и видимый расход токенов на каждом шаге.

## Positioning

Не чат-мессенджер, а «испытательный стенд рассуждений»: приборная панель вокруг агентного цикла — ход работы, инструменты и расход токенов видны на каждом ответе.

## Operating Context

Запуск локально (localhost:8080) или в Docker; вечернее использование в тёмной комнате. Сессии короткие и экспериментальные: задал вопрос — посмотрел ход работы агента — сравнил ответы и расход токенов. Язык интерфейса — русский.

## User Scenarios

1. **Вход по ПИН.** Вместо консоли — гейт входа: список пользователей (клавиши-аннунциаторы), выбор, 4-значный ПИН под подписью «ВВЕДИТЕ ПИН пользователя» → консоль. Неверный ПИН — русская ошибка, поле очищается; после трёх неудач — короткий кулдаун (429 с текстом сервера).
2. **Создание пользователя.** Кнопка «Создать пользователя»: имя (1–25 символов: кириллица, латиница, цифры, спецсимволы) + ПИН из 4 цифр → автоматический вход. Восстановить забытый ПИН нельзя — его запоминают.
3. **Онбординг-опросник.** Сразу после создания открывается визард из 7 вопросов: форма обращения (ты/вы/пилот/гонщик), тон (формальный/дружелюбный/панибратский/роботизированный), язык (Русский/Английский), структура ответов (таблицы/текст/стихи/иное), длина ответов (кратко/средне/развёрнуто, с ориентиром ≈1/3/10 тыс. токенов), избегаемые темы, интересы. Прерывание (Esc) ничего не сохраняет — работают серверные дефолты; «Сохранить» сохраняет все 7 полей.
4. **Консоль с чипом.** Имя текущего пользователя — чип с лампой в шапке; в панели «Приборы» — секция «Предпочтения»: табло из 7 значений и клавиша «Изменить в опроснике».
5. **Переключение и выход.** Меню чипа — «Сменить пользователя» или «Выйти» → возврат к гейту. Бортовое состояние консоли (журнал, сессии, ветки, память, топливомер) при этом чистится: новый пользователь видит только свои данные.
6. **Перезапуск сервера.** Токен живёт в памяти сервера: после рестарта все вкладки снова у гейта (повторный вход), данные не теряются — они на диске, разложенные по пользователям.

## Capabilities and Constraints

- Чат: отправка сообщения, ответ в Markdown (highlight.js), индикатор «печатает», счётчик токенов за сессию и токены каждого ответа.
- Панель параметров (сейчас слева, на мобильных — drawer): температура, максимум токенов (бюджет всего ответа), Top P, стоп-последовательность.
- Бэкенд ведёт агентный цикл (несколько вызовов API с инструментами); ответ приходит одной порцией, ход работы — потоком событий.
- Пользователи и вход: список пользователей, вход по 4-значному ПИН, создание пользователя (имя ≤25); токен живёт на время вкладки (sessionStorage), любой 401 возвращает к гейту.
- Предпочтения (опросник из 7 вопросов): форма обращения, тон, язык, структура ответов, длина ответов, избегаемые темы, интересы. Сервер прикладывает блок «Предпочтения пользователя» к каждому запросу модели — во всех режимах, без блока остаются только служебные под-вызовы (судья, экстрактор, сводка).
- Ограничение: фронтенд — прод-сборка, её отдаёт Ktor (отдельного фронтенд-сервера нет); новые зависимости — только по веской причине.
- Ограничение: без ролей и прав, без JWT и refresh-токенов — токен в памяти сервера, перезапуск = повторный вход для всех вкладок; смена/восстановление ПИНа не поддерживаются; удалить единственного пользователя нельзя.
- Ограничение: имена пользователей — 1–25 символов после trim (кириллица, латиница, цифры, спецсимволы; контрольные символы запрещены); ПИН — ровно 4 цифры.
- Ограничение: изоляция пользовательских данных полная — предпочтения, память, журнал обменов и сессии per-user; чужая сессия или запись по id невидима (404), чистка сессий стирает только свои.
- Ограничение: «длина ответов» — текстовая инструкция модели (ориентир ≈1/3/10 тыс. токенов), а жёсткий бюджет всего ответа задаёт параметр «Топливо» (максимум токенов) — он главнее предпочтения.

## Brand Commitments

Имя приложения — «Штурман»: бортовая консоль вокруг LLM. Язык интерфейса — русский, тон — прямой, без воды.

## Evidence on Hand

Реальные ответы модели в чате (Markdown с кодом и таблицами); конфиг config.json с реальным эндпоинтом; README. Тестимониалы, метрики, логотипы — отсутствуют, фабриковать запрещено.

## Product Principles

1. Читаемость ответа — главный приоритет: Markdown, код, таблицы читаются без борьбы.
2. Параметры под рукой, но не между пользователем и чатом.
3. Ход работы агента — герой интерфейса: видно, что модель делает прямо сейчас.
4. Расход токенов — часть ответа, а не спрятанная статистика.
5. Тёмная сцена по умолчанию, но без «неоновой киберпанк-дефолтности».

## Accessibility & Inclusion

Видимый фокус клавиатуры, контраст текста по WCAG AA на тёмной теме, поддержка prefers-reduced-motion, полная работа с клавиатуры (Esc закрывает панель и т.п.).
