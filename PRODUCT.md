# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Kotlin/Ktor сервер, отдающий статику: vanilla HTML/CSS/JS (без фреймворков), marked + highlight.js с CDN. Существующий код — единственный источник стека.

## Users

Один основной пользователь — разработчик (владелец проекта). Работает вечером, в тёмной комнате, за Mac. Использует приложение как личную лабораторию для общения с LLM через OpenAI-совместимый API (deepseek-v4-flash на собственном gpustack-инстансе) и для экспериментов со способами рассуждения.

## Product Purpose

Локальный веб-клиент к LLM: отправить запрос — получить ответ. Уникальный механизм — агентная обработка: модель сама разбивает задачу на шаги, пользуется инструментами и показывает ход работы. Успех — быстрая проверка гипотез о поведении модели и видимый расход токенов на каждом шаге.

## Positioning

Не чат-мессенджер, а «испытательный стенд рассуждений»: приборная панель вокруг агентного цикла — ход работы, инструменты и расход токенов видны на каждом ответе.

## Operating Context

Запуск локально (localhost:8080) или в Docker; вечернее использование в тёмной комнате. Сессии короткие и экспериментальные: задал вопрос — посмотрел ход работы агента — сравнил ответы и расход токенов. Язык интерфейса — русский.

## Capabilities and Constraints

- Чат: отправка сообщения, ответ в Markdown (highlight.js), индикатор «печатает», счётчик токенов за сессию и токены каждого ответа.
- Панель параметров (сейчас слева, на мобильных — drawer): температура, максимум токенов (бюджет всего ответа), Top P, стоп-последовательность.
- Бэкенд ведёт агентный цикл (несколько вызовов API с инструментами); ответ приходит одной порцией, ход работы — потоком событий.
- Ограничение: без сборщиков и фреймворков фронтенда; статика обслуживается Ktor; CDN-скрипты (marked, highlight.js) доступны.

## Brand Commitments

Имя приложения предлагается в рамках текущего редизайна (решение принимается пользователем на раунде направления); язык интерфейса — русский, тон — прямой, без воды.

## Evidence on Hand

Реальные ответы модели в чате (Markdown с кодом и таблицами); конфиг config.json с реальным эндпоинтом; README. Тестимониалы, метрики, логотипы — отсутствуют, фабриковать запрещено.

## Product Principles

1. Читаемость ответа — главный приоритет: Markdown, код, таблицы читаются без борьбы.
2. Параметры под рукой, но не между пользователем и чатом.
3. Ход работы агента — герой интерфейса: видно, что модель делает прямо сейчас.
4. Расход токенов — часть ответа, а не спрятанная статистика.
5. Тёмная сцена по умолчанию, но без «неоновой киберпанк-дефолтности».

## Accessibility & Inclusion

Видимый фокус клавиатуры, контраст текста по WCAG AA на тёмной теме, поддержка prefers-reduced-motion, полная работа с клавиатуры (Esc закрывает панель и т.п.).
