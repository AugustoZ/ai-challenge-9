# README — «Штурман»: локальный Telegram-бот

Telegram-бот **@shturman_mcp_bot**, который отвечает на вопросы по документации
проекта «Штурман» (веб-стенд рассуждений + Telegram-бот) **полностью локально** —
локальная LLM + локальный векторный поиск. Ни один пользовательский запрос не
уходит в облако.

Команды: `/ask <вопрос>` (ответ по базе знаний), `/deps` (карта зависимостей
кода), `/create` (черновик GitHub-issue), `/admin`, `/help`. Свободный текст —
тоже вопрос (RAG с фолбэком на plain-ответ). Присланные файлы (до 5) сравниваются
с веткой `main` на GitHub; при активном черновике `/create` — прикладываются к issue.

Этот README — инструкция по развёртыванию на **другом компьютере/сервере**.
Внутренняя схема работы (компоненты, потоки данных, жизненный цикл вопроса) — в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

## Состав стека

| Компонент | Что делает | Порт |
|---|---|---|
| **LM Studio** | Локальная LLM (OpenAI-совместимый API) | `:1234/v1` |
| **RAG sidecar** | Векторный поиск по корпусу: эмбеддинги E5 + FAISS + реранк. Внешний сервис — живёт в отдельном репозитории индексера, здесь не описывается | `:18702/search` |
| **bot_responder** | Единственный `getUpdates`-поллер на токен; отвечает, пишет в БД | длинный poll → Telegram |
| `tg_server` (опц.) | MCP-сервер: reader-режим (снапшот, без токена) или самостоятельный сборщик (с токеном) | stdio |
| `wiki_server` | MCP-сервер Wiki.js FAQ — **остался** в репозитории ai-challenge-9 | stdio |

## Требования

- **Python ≥ 3.12** (`shturman-bot`).
- **RAG sidecar**, поднятый отдельно (см. документацию репозитория индексера);
  боту нужен только его URL (`RAG_SEARCH_URL`) и путь к корпусу (`RAG_DOCS_ROOT`).
- **LM Studio** (или любой OpenAI-совместимый сервер локальной модели).
- **Диск**: модель 8B (~6 ГБ) + E5 (~470 МБ) + реранкер `BAAI/bge-reranker-v2-m3` (~2.2 ГБ) + FAISS-индекс.
- **GPU** желателен (эмбеддинги/реранк на GPU заметно быстрее); CPU тоже работает, но медленнее.

> **Headless-сервер / Linux без GUI**: LM Studio — GUI-приложение. Для чистого
> сервера используйте его headless-режим (`lmstudio serve`) или любой
> OpenAI-совместимый сервер (например, `llama-server`/`vllm`) и укажите его
> в `LM_API_BASE`. Всё остальное работает одинаково.

## Шаг 1. Python + venv

```bash
cd shturman-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # mcp==1.30.0, httpx==0.28.1, telethon>=1.34
```

> Версии `mcp`/`httpx` зафиксированы не случайно: в mcp 2.x `FastMCP`
> переименован в `MCPServer` — код серверов написан под 1.x API.

## Шаг 2. Локальная LLM

1. Установите и запустите LM Studio, загрузите модель генерации.
2. Включите **«Keep model in memory»** и выключите **«Just-in-Time Model Loading»**
   — иначе модель выгружается по TTL простоя и «холодный» вопрос переплачивает
   префилл (30–60 с недоступности).
3. Проверка API:
   ```bash
   curl -s http://localhost:1234/v1/models
   ```
4. Если другой сервер — задайте `LM_API_BASE` (по умолчанию `http://localhost:1234/v1`).

## Шаг 3. RAG sidecar

Sidecar поиска — **внешний сервис** (отдельный репозиторий индексера): сборка
индекса, запуск serve и настройка корпуса описаны в его собственной документации.
Боту со своей стороны нужны две переменные:

- `RAG_SEARCH_URL` — URL поиска (по умолчанию `http://127.0.0.1:18702/search`);
- `RAG_DOCS_ROOT` — корень корпуса `.md` (первоисточники для гидрации секций
  и подтяжки полных страниц по маркеру `<doc>…</doc>`).

Проверка доступности:
```bash
curl -s -X POST http://127.0.0.1:18702/search \
  -H 'Content-Type: application/json' -d '{"query":"предпочтения","k":1}'
```

## Шаг 4. Конфигурация бота

Токен/чат берутся из env или, как фолбэк, из `<repo-root>/config.json`
(`mcp[].env.TG_BOT_TOKEN`). Переменные окружения (`bot_responder.py`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TG_BOT_TOKEN` | фолбэк `../config.json` | токен от @BotFather (`/newbot`) |
| `TG_CHAT` | `tank_dargo_h6_chat` | целевой чат (username или числовой id) |
| `TG_DB_FILE` | `<проект>/.tg_messages.db` | SQLite-база (сообщения + статистика) |
| `TG_RETENTION_DAYS` | `0` | >0 — хранить сообщения не старше N дней |
| `TG_API_BASE` | `https://api.telegram.org` | для локальных тестов |
| `LM_API_BASE` | `http://localhost:1234/v1` | OpenAI-совместимый API LLM |
| `LM_MODEL` | — (задавайте явно) | модель генерации |
| `LM_MAX_TOKENS` | `2048` | бюджет генерации |
| `LM_TEMPERATURE` | `0.1` | температура |
| `RAG_SEARCH_URL` | `http://127.0.0.1:18702/search` | поисковый sidecar |
| `RAG_K` | `5` | сколько чанков надо |
| `RAG_STRATEGY` | `structure` | стратегия индекса |
| `RAG_DOCS_ROOT` | `<репо>/docs` | корпус (для гидрации секций) |
| `BOT_ADMIN_USERNAMES` | `AugustoTruck,kmnivan` | админы `/admin` (через запятую) |
| `FILEDIFF_REF` | `main` | ветка сравнения для присланных файлов |

### Наблюдатель GitHub PR (`github_watcher.py`)

Опрашивает `GET /repos/{owner}/{repo}/pulls?state=open` раз в 30 c и
уведомляет о новых PR в чат; список открытых PR подмешивается в
system-промпт обычных ответов (LLM «знает» про PR). Конфиг — секция
`github` в `config.json` (см. `config.example.json`); env-override:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GH_TOKEN` / `GITHUB_PERSONAL_ACCESS_TOKEN` | секция `github.token` | PAT GitHub (read-доступ к repo) |
| `GITHUB_REPOS` | секция `github.repos` | репозитории через запятую (`owner/name`) |
| `GH_CHATS` | секция `github.chats`, иначе `TG_CHAT` | чаты уведомлений через запятую |
| `GH_POLL_INTERVAL` | `30` (мин. 5) | интервал опроса, сек |

Первый проход после старта — baseline: открытые PR фиксируются в таблице
`github_prs` (дедуп по `(repo, number)`) без уведомления. Закрытый между
опросами PR уведомления не получит (ограничение поллера).

### AI-ревью PR (`pr_review.py`)

На каждый новый PR (после уведомления в чат) запускается поток ревью
отдельной задачей:

1. Админам из `BOT_ADMIN_USERNAMES` — в личку: найден PR + ссылка. Логины
   резолвятся по `bot_users` (бот не может писать тем, кто не начинал
   с ним диалог); числовые id — напрямую. Нерезолвленные — warning.
2. Список файлов `GET /pulls/{n}/files`: каждый файл с текстовым диффом —
   отдельным сообщением (удалённые строки `<s>`-зачёркнуты, добавленные
   `<i>`-курсивом, контекст `<code>`); бинарные/переименования — помечаются.
3. `AGENTS.md`/`SKILL.md` из ветки PR (если есть) — документами
   (`sendDocument`).
4. Сопроводительный текст: «Состав PR с дифами… передаю на обработку для
   `<модель>`» (имя из `LM_MODEL`).
5. LLM-ревью: описание PR + диффы + инструкции -> вердикт (Резюме /
   Проблемы / Соответствие инструкциям / Вердикт) админам в личку.

Капы промпта (env): `PR_PATCH_CAP` (8000 симв. на дифф файла),
`PR_DOC_CAP` (6000 симв. на AGENTS.md/SKILL.md); при обрезке в промпте
стоит явная пометка. Для PR с правами записи PAT create-тестов не
требуется: ревью читает только содержимое.

## Шаг 5. Запуск (хост-режим)

Ручной старт поллера (env — явно; дефолты в коде устаревших портов не трогают):

```bash
TG_BOT_TOKEN=... \
LM_API_BASE=http://localhost:1234/v1 LM_MODEL=<модель> \
RAG_SEARCH_URL=http://127.0.0.1:18702/search \
RAG_DOCS_ROOT=<абсолютный путь к корпусу> \
nohup .venv/bin/python bot_responder.py >> .bot_responder.log 2>&1 &
echo $! > .bot_responder.pid
```

Лог — `.bot_responder.log`, PID — `.bot_responder.pid`. Признак здоровья:
INFO-строки старта в логе и ни одной `409` после них.

## Шаг 6. Проверка

- `/admin` в Telegram от админа → отчёт (токены, время работы, вопросы, юзеры, топ-10).
- Вопрос (`/ask или свободный текст`) → ответ по корпусу с указанием путей-источников.
- `tg_server`/`wiki_server` — через MCP-клиент (opencode/web), stdio.

## Автозапуск (systemd, Linux-сервер)

Пример юнита для `bot_responder` (`/etc/systemd/system/shturman-bot.service`):

```ini
[Unit]
Description=Shturman bot responder
After=network.target

[Service]
WorkingDirectory=/opt/shturman/shturman-bot
Environment=TG_BOT_TOKEN=ВАШ_ТОКЕН
Environment=LM_API_BASE=http://localhost:1234/v1
Environment=RAG_SEARCH_URL=http://127.0.0.1:18702/search
ExecStart=/opt/shturman/shturman-bot/.venv/bin/python bot_responder.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Через `User=` ограничьте права. LM Studio и RAG sidecar — отдельные сервисы.

## Админ-панель

`/admin` — только для списка из `BOT_ADMIN_USERNAMES` (по умолчанию
`AugustoTruck,kmnivan`; регистронезависимо, `@` игнорируется). Посторонний `/admin`
получает **молчание**. Отчёт: токены всего (prompt/completion) и за сессию, время
работы, число вопросов, последние 5 пользователей, топ-10 вопросов. Токены копятся
из `usage` ответа LM Studio; вопросы/юзеры — из таблиц `bot_questions`/`bot_users`.
Их можно бэкфиллить из логов LM Studio (`stat_*` в `meta`).

## Безопасность

- **Секреты — только в env/конфиге.** `config*.json` уже в `.gitignore`
  (исключение — `config.example.json`). Токен бота не логируем и не коммитим.
- **stdout MCP-серверов = только JSON-RPC**, все логи — в stderr.
- **Один поллер на токен.** `tg_server` при работающем боте запускайте в
  **reader-режиме**: без `TG_BOT_TOKEN`, `TG_DB_FILE`=снапшот, `TG_DB_READONLY=1`
  — тогда его поллер не стартует (чтение работает, если в снапшоте уже есть
  сообщения). Токен в `tg_server` включает его собственный поллер → взаимный
  `HTTP 409` с ботом.

## Устранение неполадок

| Проблема | Причина / решение |
|---|---|
| `HTTP 409` | второй `getUpdates`-поллер: дубликат хостового `bot_responder`, либо `tg_server` с токеном. Поллер — один. |
| `tg_server`: «Токен бота не задан» при чтении | reader-режим читает только непустое хранилище: снапшот пуст (бот ещё не собирал сообщения) — наполнится при работающем боте; либо это сценарий «сборщик» → нужен токен (и тогда бот остановлен). |
| Модель «выгружается», холодный вопрос 30–60 с | JIT-загрузка. В LM Studio: «Keep model in memory» + JIT off. |
| `Metal GPU Timeout`/`SubmissionsIgnored` | реранкер и MLX-движок делят GPU. Реранкер на `device=auto`/MPS; снизить частоту бурстов (контактовый интент — без реранка). |
| CPU-реранк убивает процесс | `faiss-cpu` импортирован до загрузки torch-модели → процесс молча падает. Не смешивайте CPU-эмбеддер с CUDA-реранком; оставьте `device=auto`. |
| `RAG_DOCS_ROOT`/корпус не найден | задать абсолютный путь в `RAG_DOCS_ROOT` при старте бота. |
| `sidecar` не отвечает | не собран индекс, модель не скачана, порт занят — см. документацию репозитория индексера. |
| Нет ответа / «Не уложился в лимит» | уменьшить вопрос; для reasoning-моделей увеличить `LM_MAX_TOKENS` и оставить `/no_think` в системном промпте. |
