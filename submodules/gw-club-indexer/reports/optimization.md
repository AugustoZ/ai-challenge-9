## Наблюдения

- **max_tokens:** 1024 (9.18) заметно лучше 512 (8.28) — reasoning-моделям нужен бюджет на размышления, иначе answer обрезается (`finish_reason=length`).
- **Промпт-шаблон:** оптимизированный (8.94) против наивного (8.52) — разница в пределах вариативности модели; оптимизированный стабильно короче, а потому быстрее и не даёт просадки по качеству.
- **k (топ-чанки):** k=3 (8.99) против k=5 (8.46) — существенного выигрыша от большего k нет; k=5 даёт более полный контекст (заметно увеличивает t_gen), k=3 быстрее.
- **temperature:** 0.1/0.3/0.7 дают схожий judge; низкие значения (0.1–0.3) предпочтительнее для короткого, предсказуемого ответа бота.
- Абсолютные judge-баллы высоки (~8–9.7) для всех ячеек — RAG-ответы по корпусу близки к потолку; различия внутри ~1 п.п. следует читать с учётом вариативности модели и судьи.

## Квантование

В кэше моделей LM Studio доступен только один квант — MLX 4-bit (`Qwen3-8B-MLX-4bit`). Альтернативных квантов (FP16/INT8) для сравнения нет, поэтому пункт SDD «сравнить кванты» зафиксирован как **недоступно на текущем наборе моделей** (не блокирует день).

## Рекомендация («после»)

Лучшая ячейка по judge-баллу при приемлемой латентности: **t=0.1,mt=1024,k=5,p=opt**
→ judge **9.5**, t_gen **6.951 с**, tokens/с 41.0

Прирост против baseline: Δjudge = +2.90 п.п. (baseline judge 6.6 → 9.5). Baseline замерен на 5 из 6 вопросов (1 вопрос дал пустой ответ из-за short-context — потребовал большего max_tokens), что и объясняет его заниженный балл по сравнению с ячейкой t=0.7,mt=512,k=5,naive в матрице.

## Рекомендуемая конфигурация для bot_responder

```ini
# Модель
LLM_MODEL=qwen3-8b-mlx
LM_STUDIO_URL=http://localhost:1235/v1
# t=0.1,mt=1024,k=5,p=opt
TEMPERATURE=0.1
MAX_TOKENS=1024
RAG_TOP_K=5
PROMPT_TEMPLATE=optimized
RAG_STRATEGY=structure
# Для reasoning-модели max_tokens обязан быть >= 1024, иначе content пустой.
```
